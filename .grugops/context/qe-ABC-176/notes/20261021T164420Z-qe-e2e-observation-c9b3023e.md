# ABC-176 QE: the SE's ordering risk measured. The guard line preceded the JSON report in 46 of 46 refusal runs; the mechanism holds on vitest 4.1.11, and no row pins it

- **Why it matters (counterfactual).** `printf '{"numPendingTests":0,"numTodoTests":0}\nheap-guard: refused. X\n' | jq '.numPendingTests + .numTodoTests'` prints `0` and exits 5. So with the order reversed, A1's "no integer" clause fails, even though the exit status stays non-zero.
- **Measured.** Each run: refusal arm, `--reporter=json 2>/dev/null`. Pass = line 1 is `heap-guard: refused.`, line 2 opens the JSON, vitest exits 1, and jq prints nothing:
  - direct `vitest run`, SUITE: 10/10; direct, ONE-FILE: 10/10;
  - under `node tools/grugops/run-bounded.js 60000 vitest run …`, SUITE: 10/10; ONE-FILE: 10/10;
  - under the wrapper with a slow consumer (`| (sleep 2; cat)`), SUITE and ONE-FILE x3: 6/6.
- **Mechanism (read in `node_modules/vitest/dist/chunks/cli-api.CnMVyzaz.js`).** In `runFiles`, `await this.initializeGlobalSetup(specs)` (the guard) comes before the `finally` that calls `_testRun.end` → `onTestRunEnd` → JSON `writeReport` → `logger.log(report)`. vitest's `Logger` is a `new Console({ stdout: process.stdout })`, the same `process.stdout` Writable the guard writes to. One Writable is FIFO, so the order holds even with async pipe writes. The wrapper inherits stdio (one fd), so it cannot reorder. `state.clearErrors()` runs before global setup, so the `catchError`ed refusal survives into `getUnhandledErrors()`.
- **Residual.** This is vitest-internal order, not a documented contract. No row pins it: the in-suite rows use a stub stream. On a vitest bump, the reporter header's re-run set (seven rows) re-reads the result file (A3) but not the capture arm (A1/A2). → `QE-176-b`.
- Not measured: a refusal with any reporter other than `json` on stdout (no AGENTS.md line spells one).
