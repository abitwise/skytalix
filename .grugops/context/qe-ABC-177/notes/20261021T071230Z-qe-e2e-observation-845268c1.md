# `ABC-177` timing-3: gaps and instrument risks found this hop (none changed a grade)

1. **`sampler174.mjs` (registered, `83409bc0e70b`) can crash.** In t3-r2, about 07:01:3xZ, it threw
   `TypeError: Cannot read properties of null (reading '1')` at line 15. The cause is a `ps -axo pid=,ppid=,uid=,command=` line
   that its `^(\d+)\s+(\d+)\s+(\d+)\s+(.*)$` parse does not match. Which line it was is `UNKNOWN - verify`: it was not captured.
   Candidates are a command containing a newline (another session's multi-line `bash -c`) or a process with an empty command.
   - **Effect:** sampler coverage ended about 3 min before the lane did; the last row is 07:01:28Z.
   - `run-amended.sh`'s later `kill -TERM` printed "No such process".
   - The strict readout discards on `sampler` (9 of 16 H/H2 runs carry it). The amended readout logs it.
   - **No grade moved.** Thermal VOIDs t3-r2 under either view.
   - Not fixed. Fixing it is not QE's call: the instrument is registered. **Risk:** any future reading can lose its sampler
     mid-stage while foreign sessions run.
2. **The start gate's full-suite rule let a sustained multi-file foreign run through.** `gate3.sh` blocks only on a
   `vitest run` with no test-file token. In t3-r2 the other session ran back-to-back multi-file runs: 157/181 window polls,
   and `foreign_vitest` 3–4 on every lane run. Owner amendment `…f8cd47ba` (about 06:50Z) has since made every foreign run,
   full suites included, non-blocking. So the rule is now moot. It is recorded because the t3-r2 stage ran beside this load.
3. **Thermal 0 for 60 s is a weak cool-down signal.** After t3-r1, `thermalpressurelevel` was back to 0 within about 66 s of
   the lane ending (06:53:10Z). t3-r2 still went to 1 in its first round, and to 2 in its second. The level clears faster than
   the chassis cools, so the gate cannot tell a cooled host from a heat-soaked one.
4. **`npm ci` under npm 11.20.0** did not run esbuild's `postinstall` or fsevents' `install` script (its `allowScripts`
   default; logged in `arms-build/npmci-*.log`). Every arm still ran 59 files and 1987 tests in round 0 and every run, so there
   was no functional effect. Whether timing-2's arms had the same npm behaviour is `UNKNOWN - verify`: their `npm ci` logs
   were not kept.
5. **Ordering record.** `preregistration-timing3.txt` (mtime 06:38:58Z) and `gate3.sh` (06:38:25Z) were written before the
   first gate poll (06:39:03Z). The Orchestrator's commit `478b3b9b` (06:56:16Z) picked both up, after t3-r1 had run.
   - The commit does not prove the ordering. The file mtimes are its only record, and mtimes can be altered.
   - The committed blobs are byte-identical to the working files (empty `git diff`), with sha256 prefixes `978a3c11d8c5` and
     `34822376dc21`.
