# Failed attempt: ABC-209's per-game transposition table did not show a GAIN under S1. Pooled D over 800 games is NEUTRAL, +8.69 ± 18.25 (d1 −0.9 ± 25.3, d2 +18.3 ± 26.3), at B = 1 500 ms against base 64394974. Not merged

- **What was tried:** the `ADR-0025` decision 4 amendment (accepted by the owner, `…2ae5fc12`): the transposition table kept
  across one game's searches while the caller's game token continues, cleared otherwise. Size 4 MiB, always replace, no
  ageing. Build `grugops/ABC-209` `bb6cf451`; measured at the QE merge `b5f46e86`.
- **The measurement:** one pre-registered run under `…4c3f7639`: D d1 NEUTRAL, then the one S1 extension d2 NEUTRAL; pooled
  W/L/D 240/220/340, X − Y = −9.56. 0 faults, 0 foreign vitest; the grade holds load-free and split by power source.
- **It was a fair test of the idea:** each D game ran in one engine process, and 98.2 % / 98.3 % of the candidate's searches
  kept the table. The gate passed (A1–A5, A7 MET; G2, G6 MET), so the result is not a build defect.
- **What it means:** `ADR-0025` falsifier `T1` holds: a per-search lifetime is enough at this budget, by this measure. The
  record from the design hop (moves 2–8 cost 0.94–0.97× of fresh at fixed d7) was a small node saving, and it did not turn
  into a measurable strength gain at 1 500 ms per move.
- **Do not retry as is.** A re-tune reading needs the owner's word (page `A6`); BA/PM allows at most one re-tune round per
  ticket (EPIC-008 S1). Anything retried should change what is kept or how it is used, not re-read the same build: `T5`
  (a generation or depth-preferred replacement) is the ADR's named next question.
- **Status:** branch not merged; the ticket goes back to BA/PM under S1; the amendment's dated line "accepted, not in force on
  main" is the Architect's (as the amendment states).
