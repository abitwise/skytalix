## A5: what is MET
The run exits 0 with both blocks played, and all of the following hold:
1. **`start=` honoured:** neither build has a coverage cause. QE's own check also holds: each block's 10 PGN rounds
   start from EPD lines 1–10 (placement and side to move), with skytalix playing once per colour.
2. **`nps.log`:** exactly 2 lines, one per block per build, each with a numeric median and `moves_ge_400ms` > 0.
3. **`thermal.log`:** Tctl is numeric (k10temp, not `?`) on every line. The sample count is ≥ ⌊span / 10 s⌋ over
   `schedule.log`'s span, and the largest gap between samples is ≤ 12 s.
4. **Formula:** each block's printed `Elo difference` line equals the pooling formula. That is the tool's own check
   (no formula cause) plus QE's independent copy of cutechess-cli 1.5.1's formula, run on the block's W/L/D.
5. **Host-path scan:** every file under `<out>` except `clone-*` is clean. It has no home, temp, session-scratch,
   system-binary or node-manager path prefix. Case-sensitive, it has no login name, host name or e-mail (address or
   local part). `SHA256SUMS` verifies. The patterns are kept in the session, not in this record.
   The engine's `id author` line in `artifacts.txt` is ruled on separately.
6. **Summary:** `summary.txt` has both builds, the pair line, the pair state and the pentanomial line.

**Halt rule.** A game-level fault (illegal move, disconnect, stall, time loss) makes the tool halt and read
UNRESOLVED. That is A4 working, not an A5 miss. QE records it and re-runs once (`EPIC-008` "re-run once"). If the
re-run halts too, A5 is NOT MET. A tool defect (wrong argv, crash, a miscount, a leak) means STOP: QE reports it and
does not fix it.

## A6: what is reported
- **Play wall:** first `start` to last `end` in `schedule.log`.
- **Build time:** `host.log` `before` to the first block start.
- **Total:** session start to exit.
- **Projection for the 400-game pair:** play wall × 10, plus one build time, plus 9 block gaps. It is set against
  the ≤ 10 h target and the R rate of 44–46 games/h.
- A projection above 10 h is a named gap (PASS_WITH_GAPS), routed to BA/PM. It is not a FAIL: A6's criterion is
  that the wall is reported and projected.
- A run longer than about 2 h continues, and QE records why.

## Verdict rules
- **PASS:** A1–A4 reproduced by QE, A5 MET, A6 reported within the target, and no blocking gap.
- **PASS_WITH_GAPS:** the same, with non-blocking gaps named.
- **FAIL:** A1–A4 not reproduced, a tool defect, a host-path leak, or A5 NOT MET after the one re-run.
