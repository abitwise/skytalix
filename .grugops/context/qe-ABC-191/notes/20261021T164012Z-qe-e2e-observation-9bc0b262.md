## `QE-191-a` (LOW, proposed; beyond `AR-188-BINARY`'s term)
The one diff call reads `--text --no-textconv`, but it still takes git's external-diff, colour and prefix settings. Measured in a scratch clone at `e0bc26fe` on X1's edit:

| route (clone-local config or env only) | head limb 1 | base limb 1 | stand-in `--numstat \| awk '$1=="-"'` |
|---|---|---|---|
| Q15: committed `src/** diff=ext`, plus `diff.ext.command` = a script that prints nothing | silent | silent | prints nothing (`1 3`) |
| Q16: `GIT_EXTERNAL_DIFF` = the same script | silent | silent | prints nothing |
| Q17: `color.diff=always` | silent | | prints nothing |
| Q18: `diff.srcPrefix=x/`, `diff.dstPrefix=y/` | silent | | |
| Q19: `diff.noprefix=true` | FIRES 1/3 (harmless) | | |
| Q20: `diff.mnemonicPrefix=true` | FIRES 1/3 (harmless) | | |

- **Why LOW:** each route needs the operator's own git config or environment. A committed attribute alone does nothing without a configured `command`. This host sets none today (`color.ui=auto`, which is off on a pipe; no `diff.*.command`; no `GIT_EXTERNAL_DIFF`). The `--numstat` stand-in never caught these routes either, so **retiring it loses no cover** here. It is the same precondition class as the textconv route the page took in scope (a configured driver), but it is not a "file git treats as binary".
- **Candidate flags for the fix owner (not tried by QE; `UNKNOWN - verify`):** `--no-ext-diff`, `--no-color`, and explicit `--src-prefix=a/ --dst-prefix=b/` on the same argv.

## `QE-191-b` (INFO; already on base; out of scope)
A production file whose name holds a non-ASCII byte (QU: a new `src/qé.ts` holding `import { readFileSync } from "node:fs"`) is quoted by git's `core.quotePath` in both `ls-tree` and `diff` (`"src/q\303\251.ts"`). `isProduction` then rejects it, and every limb is blind to it on head and on base. When a production file imports it (QU2: `cli.ts` gains `import "./qé.ts"`), limb 1 FIRES (disputed) through the unresolved-edge fail-safe. So only an unreached file stays unseen.

## `QE-191-c` (INFO; the `R-188-b` class, carried)
`mk` checks a plant's file list, not each edit. If the JSDoc line `` * `ABC-095` `` drifts, `BIN-NUL`'s NUL substitution becomes a no-op, and the row silently re-runs X1. At head it still reads `ok` (FIRES, `@<base>`). Its teeth then show only in A2 (base instrument red on `BIN-NUL`) or in A5's count (2/4, not X1's 1/3). **Reading rule:** whenever the harness is re-run, read `BIN-NUL`'s count as 2/4. `R-191-a` (the `BIN-ATTR` header line is unpadded) is confirmed cosmetic.

So the stand-in retires exactly as far as the instrument now covers binary-flagged production files: every NUL and attribute route QE tried (n2) fires.
