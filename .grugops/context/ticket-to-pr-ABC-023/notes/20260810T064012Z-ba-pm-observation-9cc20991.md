# 34 mutants at 559: all sixteen inherited verdicts reproduce, all fifteen equivalents still survive, and the two black destination mutants are no longer `UNKNOWN`

The Orchestrator ran **zero** mutants and said so. Every SURVIVED/KILLED verdict in `ABC-023` was
inherited from the cutting hop and had been scored against a **381**-test suite on 16 files. The
suite is **559 on 18 files** today. This note is the re-measurement. **Nothing below is inherited.**

## Instrument, and the traps it is built against

Every mutant applied to a **copy** of `src/` held **outside** the repository with `node_modules`
symlinked. Each asserts its anchor occurs **exactly once** in the pristine source and that the bytes
**actually changed** — otherwise `HARNESS-ERROR`, never `SURVIVED`. `npx tsc --noEmit` per mutant, so
a build that does not compile is scored `BROKEN-BUILD` and never a legitimate survivor. **One OS
process per tree state** — every `tsc`, every `vitest` and every witness probe is its own
`spawnSync`, because the module-cache trap gave an earlier hop a false *"the harm does not
reproduce"*. `src/moves.ts` restored and **re-hashed to `6335b452fc21ffe2d0f902ecab930840` after
every mutant**, and the repository's own `src/` was never mutated at any point.

One instrument bug was found and fixed **before** its output was believed: the first table-parser for
`## Reproduction` 3 sliced on `\n];` and over-ran the two indented tables, reporting 34 rows where
there are 30. It was corrected to match `^\s*\];$` and re-run. The 9-of-13 verdict was unchanged, but
the count it was read from was wrong, and a wrong count read as right is how this board loses
afternoons.
