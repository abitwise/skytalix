# `ABC-015` PASSES — `In Review` → `In Security/NFR`. The implementation is right; the SUITE was thin

The `In Review` exit is this role's, and it is taken. **`In Review` 1/3 → 0/3, `In Security/NFR`
0/2 → 1/2.** No limit approached, no override taken. **Nothing merged and nothing deployed — a human
holds both.**

## Why PASS and not a send-back, stated so the bar is visible

**A send-back was live and was rejected on one ground: nothing is wrong with the delivered
behaviour.** All eleven acceptance criteria are implemented, tested and passing. Every one of the
three defects the campaign found is a **mutant that the tests failed to exclude**, not a defect the
code contains. `src/glyph-mode.ts` is byte-identical to the Engineer's (`md5
9c1f4f4e957d4faf3c9cccc49a545185`) after 58 mutate-and-restore cycles, and it is byte-identical
because it never needed changing.

**What would have earned a FAIL, stated so the bar is checkable:** a criterion that does not hold, a
mutant that survives *and* names a defect actually present in the tree, a gate that will not go
green, a skipped or fabricated test, or a hole this role could not close without changing production
code. **None of those is present.** Writing the missing tests is QE's own job, not a round-trip: a
send-back whose only content is "QE did not write the tests QE is here to write" would be passing my
own work back up the chain.

**And a green-badge PASS was equally rejected.** Three mutants that were real production defects
passed all eleven criteria and all 271 delivered tests. Handing that forward as "271 green" would
have been the exact failure this project has now recorded four times.

## What changed, and the hard limit that shaped it

**TESTS ONLY. No production-code fix, no hidden scope.** Six tests added and one guard table widened:

- **four conflicting-value locale-precedence rows** — each sets two or three of `LC_ALL` /
  `LC_CTYPE` / `LANG` **against each other**, so exactly one rung can produce the expected answer.
  This is the ticket's own `## Test notes` obligation, discharged for the rung that was missing it;
- **one absent-`isTTY` session test** — deletes the property rather than setting it `false`, which
  is the only shape a non-TTY process presents;
- **one eager-not-lazy session test** — moves the ambient **between** `beginGlyphModeSession` and
  the first request, the window criterion 11 cannot see;
- **`node:fs/promises` added to the `NFR-007` guard's spied filesystem table** — the async half of a
  guard that already named the sync half. Not a new bar.

**28 of 29 mutants now die.** The one survivor is proven equivalent and is reported, not papered
over.

## The four things this PASS does NOT do

1. **It does not discharge the three spec-level items.** Two were already queued for BA/PM (criteria
   10/11 blind to a single-signal session; the empty-locale ruling) and **this pass adds a third**:
   **criterion 6 is itself the one-at-a-time shape the ticket's `## Test notes` forbid**, so the
   *criteria*, not just the delivered suite, under-specify the `LC_CTYPE` rung. All three now have
   tests behind them; none of them has a corrected criterion. **Amending an acceptance criterion is
   the `Backlog` exit and it is not this role's.** They belong in the one BA/PM hop the Orchestrator
   already sequenced.
2. **It does not ratify the empty-locale ruling — it concurs with it and leaves it open.** The
   Engineer recorded `confidence: medium` and asked for it to be read rather than inherited. Read:
   **QE concurs**, on the Engineer's own ground — this ticket's row-4 rationale forbids turning a
   content-free variable into a negative signal, and `LANG=` carries no information. It stays a
   product question because it can change code, and it stays BA/PM's.
3. **It does not close the E2E slot, and it reports why rather than filling it.** `quality.ui_e2e`
   is `ui-or-critical-path`; `AGENTS.md` has E2E at `UNKNOWN - verify`; there is no CLI entry point
   until `EPIC-006`; and **this module has zero runtime importers today**. There is nothing to drive
   end-to-end and no runner to drive it with. **The first end-to-end exercise of this rule arrives
   with `ABC-018`** — which is also the ticket the merge-order constraint binds to, so the gap and
   the constraint close together. A fabricated E2E here would be exactly the "test claiming to check
   what a terminal renders" the ticket forbids by name.
4. **It does not authorize a merge and it does not touch the merge-order constraint.** `ABC-015`
   merges **with or before `ABC-018`**, which is unstarted and in `Backlog`; the constraint is still
   satisfiable and still binds. The gate ahead is Security/NFR's.
