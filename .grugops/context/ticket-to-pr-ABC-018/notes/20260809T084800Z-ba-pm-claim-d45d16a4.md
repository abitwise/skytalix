# What this promotion does NOT establish — soft, non-load-bearing, explicitly unverified

`confidence: UNKNOWN - verify` on the whole note. Nothing here may be cited as settled; it exists so
the next role starts from an honest edge rather than assuming the gate was exhaustive.

1. **"No further acceptance defect remains" is NOT claimed.** Five were found and fixed. The
   previous run of this gate (`ABC-015`, 2026-08-08) found two, and then a **second** BA/PM pass on
   the same ticket found four more criteria worth amending. A promotion means the ticket clears the
   Definition of Ready on this reading, not that it is exhausted.

2. **The reserved prompt row is a product ruling, not a verified design.** It matches `EPIC-002`
   `4a`'s reference layout and the fact that `ABC-018` owns all writing, but nothing has been built
   or run against it. If `EPIC-003`'s eventual input surface (readline, tab-completion) turns out to
   need more than one row, or to write outside the frame, this ruling is the thing to revisit — and
   it is `EPIC-003`'s decomposition that will find out. The rejected alternative (`R ≥ H + 1`, prompt
   outside the frame) is on the record with its reason for exactly that reason.

3. **`W` — the frame's width — is defined but not yet determined.** It is the widest row the
   assembled regions emit, and two of the three panels do not exist. The merged board is 18
   characters; `ABC-016` and `ABC-017` state their heights and not their widths. Whoever builds
   those panels sets `W`, and the `W = 18` in `ABC-018`'s criteria is a **stub fixture**, not a
   promise about the shipped frame.

4. **The arithmetic in the two candidate criteria is BA/PM arithmetic, not a measurement.** Six
   4-character SANs = 29 characters with separators; ten = 49; a 2-row region at `W = 18` holds 36
   and cannot split a token, so at most 3 per row. That is honest arithmetic over an assumed token
   length, and a real ambiguity list of longer SANs (`Rfxd1+`, `exd8=Q#`) changes the numbers. The
   criteria are written so `N` survives that — it is a count of the input — but the *"all six fit"*
   case is only true for the token lengths it names.

5. **`NFR-002`'s write half is still `UNKNOWN - verify` and this subtask did not move it.** No
   number for it is quoted here, from any note. The compute-side figures on record (171–1,318 µs for
   the SAN derive, Apple M3 / Node v24.12.0 / darwin-arm64) are a different measurement and are not
   a substitute. Both halves get measured on this ticket, separately, each with its machine and ply
   count.

6. **A near-vacuous criterion was left in place, knowingly.** Criterion 1 (identical row count at 80
   and 300 plies) cannot fail under fixed-height stub panels. It is epic `4a` verbatim and becomes
   falsifiable at integration; QE should treat it as an integration obligation for `ABC-019` /
   `EPIC-006`, not as evidence delivered by this ticket.

7. **`ABC-016`, `ABC-017` and `ABC-019` were NOT re-checked.** This subtask promoted one ticket. The
   prompt-row seam it closed was found by grepping those tickets, which is not the same as gating
   them — the same limit the `ABC-015` promotion recorded about these four, and it still holds for
   the remaining three.
