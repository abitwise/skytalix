## D2: four planted mutants, to test whether the committed proof itself would catch a regression of R2

Each mutant is a copy of the fixed `run-bounded.js` in a separate scratch directory, alongside
unmodified copies of `run-bounded.hang-fixture.js` and `run-bounded.proof.js`, so the only
variable per run is the mutation:

1. **off-by-one**: `timeoutMs > MAX_TIMEOUT_MS` changed to `timeoutMs >= MAX_TIMEOUT_MS` — moves
   the ceiling down by one, so it now rejects the boundary value `2147483647` that `A2` requires
   stay accepted.
2. **dropped**: the `timeoutMs > MAX_TIMEOUT_MS` clause removed from the `if`, restoring the
   pre-fix validation shape byte-for-byte (an isolated regression of just R2's own clause, distinct
   from D1's whole-file pre-fix reproduction).
3. **ceiling of 2^32**: `MAX_TIMEOUT_MS = 2 ** 31 - 1` changed to `2 ** 32 - 1` — a wrong ceiling
   that still lets `2147483648` (`2^31`) through, which then hits `setTimeout`'s real 32-bit clamp
   and kills a healthy target.
4. **after spawn**: the whole validation `if` moved to after the `spawn(...)` call — the target
   is already started (and, because it inherits stdio directly, already writing to the captured
   pipe) before the wrapper's own `process.exit(2)` runs, so a "rejected" row's assertion that the
   target's own marker never reaches stdout is what this mutant is built to break.
