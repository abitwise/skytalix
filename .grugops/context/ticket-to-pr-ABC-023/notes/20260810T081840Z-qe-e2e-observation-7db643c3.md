# FOURTEEN builds passed EVERY criterion, the WHOLE 578-test suite AND the deep lane at 32/32 — three gaps in the CRITERIA, none a defect in the code

The precedent said to expect this and it held for the fifth consecutive ticket. **Every one of the
fourteen is a gap in the criteria.** `src/moves.ts` is byte-identical to `main` throughout; no
survivor below is evidence that the delivered code answers any position wrongly.

Each mutant was scored `SURVIVED` only when the delivered tree reported **578 passed of 578** with
zero failures, and each survivor was then re-run against `PERFT_DEEP=1` in a **fresh process**, where
it scored **32/32**. So each passed `A1`–`A5`, `npm test`, and the opt-in lane `A4` mandates.

## Gap 7 — `A2` never varies the ATTACKER'S TYPE on the landing square (1 survivor)

```
mutant                                                  @pre       @rows      deep
the LANDING square tested only for ORTHOGONAL SLIDER
attacks (raySliderAttacks over ORTHOGONALS, ROOK)       SURVIVED   SURVIVED   32/32
                                                        559/559    578/578
```

`A2`'s four rows are `4k1r1/…`, `2r1k3/…`, `4k2r/…`, `r3k3/…` — **every one attacked by an enemy
ROOK standing on the landing square's own FILE**. That is measured, not asserted: strip the landing
square's file from any of the four and the landing square goes quiet. So a build whose landing-square
test sees only orthogonal sliders passes all four rows, and offers a castle onto a square attacked by
a knight, a pawn, a bishop, a diagonally-placed queen or the enemy king.

Witness, the FEN printed and re-parsed (`## Test notes` 7): on
`4k3/8/8/8/8/7n/8/4K2R w K - 0 1` the delivered tree offers **0** castles from `generateMoves` and
returns 8 legal moves; the mutant offers `e1g1`. `legalMoves` removes it for its own different reason
— the king would end in check — so **every count-based oracle including perft stays blind**, which is
`## Reproduction` 1's masking argument reappearing on a second axis. What breaks is the exported
`generateMoves` and its documented invariant, which is what `A2` exists to pin.

## Gap 8 — the (colour × side) COMBINATION, where `A1` and `A3` require only the two AXES (9 survivors)

`A3` requires every type to **vary** both axes. Eleven of the thirteen type/table pairs still carry
only **two or three** of the four (colour, side) combinations after `A3`'s nine rows land — only the
two QUEEN pairs carry all four. An admission conditional on colour **and** side **at once**, keyed on
an uncovered combination, therefore survives:

```

king's sq admits own BISHOP only when BLACK and QUEENSIDE     SURVIVED   SURVIVED   32/32
king's sq admits own PAWN only when WHITE and QUEENSIDE       SURVIVED   SURVIVED   32/32

rook's sq admits own PAWN only when BLACK and KINGSIDE        SURVIVED   SURVIVED   32/32
king's sq admits enemy KNIGHT only when BLACK and QUEENSIDE   SURVIVED   SURVIVED   32/32
rook's sq admits enemy PAWN only when BLACK and KINGSIDE      SURVIVED   SURVIVED   32/32
CONTROL king's sq admits own QUEEN, BLACK and QUEENSIDE       KILLED     KILLED     —

```

**The control is what makes this a gap rather than an opinion.** QUEEN is the one type whose rows
already carry all four combinations, and the identically-shaped mutant on QUEEN dies. So the class is
discriminable; the rows simply do not reach it.

The same corner sits in `A1`'s four pair rows, and this is the engineer's declared limitation 1:

```

the own-QUEEN pair, BLACK and KINGSIDE only                   SURVIVED   SURVIVED   32/32

```

`A1`'s four rows cover (white, kingside) and (black, queenside) in each family. The control keyed on
(white, kingside) — a combination a delivered row **does** carry — dies at 577/578; the two keyed on
the uncovered diagonal survive. This is one level below `A3`'s own lesson, applied to `A3` and `A1`
themselves.

## Gap 9 — the SCALAR fields, an axis no row in the file varies at all (4 survivors)

Every FEN in all six tables in `src/moves.castling.hardening.test.ts` ends `- 0 1`. A guard switched
off on any other value of those three fields is never exercised:

```
mutant                                                        @pre       @rows      deep
BOTH identity guards skipped when halfmoveClock !== 0         SURVIVED   SURVIVED   32/32
BOTH identity guards skipped when fullmoveNumber !== 1        SURVIVED   SURVIVED   32/32
BOTH identity guards skipped when an EP square is set         SURVIVED   SURVIVED   32/32
the LANDING square's through-check test skipped when
  halfmoveClock !== 0                                         SURVIVED   SURVIVED   32/32
```

The first three switch off **the entire identity guard** — `ABC-009`'s whole fix — on a slice of the
input space, and nothing notices. Perft is blind by construction: legal play never puts a wrong byte
on a home square while the right is held, so the guards reject nothing there whether they run or not,
which is `NFR-001`'s own count-based discharge (198,175 executions, zero rejections) read as a
coverage fact.
