## The two closes that do not work, and this is the load-bearing part of the hop

**1. `G1` — "`CASES` gains a `thinking: true` variant of the in-check case" kills ONE of five, not
three.** QE wrote that the single entry *"closes `m06`, `m37` and the `A10`/`A11`/`A12` sweep over it
at once, because those three are already written over `CASES`."* Measured: **the three criteria that
iterate `CASES` assert purity, row count and ASCII — none of them asserts CONTENT.** So the entry
kills `m37` (non-ASCII in the check cell while thinking, via `A12`) and leaves alive:

- `m06`, `CHECK` dropped while thinking — **378/400 games diverge, the sharpest build in QE's report**;
- `m29`, the claim cell dropped while thinking;
- `m46`, the side-to-move cell dropped while thinking.

Each would die only to a snapshot, and QE's own verdict on snapshots is *"a genuine regression net
and a poor criterion"*, discharged by a single `-u`. **A close that leaves the report's own sharpest
build alive at every criterion is not a close.**

**The replacement is one clause and it kills all five**, replacing `A7`'s width clause rather than
adding anything: *given every case in `CASES` rendered in both thinking states, replacing
`thinking...` in the busy panel with spaces of the same length yields a panel byte-identical to the
idle one.* It renders every case both ways itself, so **no new `CASES` entry is needed for the
thinking axis at all** — it is cheaper than the close it replaces and strictly stronger, and it
subsumes the row-count and per-row-width properties by byte-identity.

**2. `G3` — "one FEN closes all three" is true of each named mutant and false of the class.** A
position down `R+N+B` reads `+11`; `KNIGHT=4`, `BISHOP=4` and `ROOK=6` each read `+12` and die. But
**a compensating `KNIGHT=4, BISHOP=2` reads `4+2+5 = +11` and survives**, while three single-removal
rows read `+3 / +3 / +5` and kill it on the first. One row also cannot say WHICH integer is wrong,
and is measurably harder to check by eye — **the joint FEN was mis-built twice at this hop before it
read `+11`** (recorded as this hop's `failed-attempt`). Three rows, in a table that already exists,
iterated by a test that already loops.

## `G4` is mine, and the honest statement of it

**I ruled `A13` last hop and this is the dimension that ruling did not reach.** The rewrite fixed
what the clause **counts** and left what it counts it **on** unstated — and an unstated depth
defaults to whatever fixture is nearest, which was one ply. The clause `## Security / NFR triggers`
calls *"the part that actually binds"* was blind from ply 2. **That is this ticket's own stated
failure mode — "a bar that cannot fail on the regression it exists to catch is not a bar" — one level
down, and the previous ruling is where it should have been caught.**

One thing improved beyond the depth: **the scan clause is now stated ply-independently** — `squareAt`
= 64 + the occupied squares of `initialFen`, because `parseFen` places one piece per occupied square
and `makeMove` never calls `squareAt` at all (grepped at this hop). That is what makes a depth
requirement meaningful rather than a second magic number.
