# QE/E2E: QE-204-h (LOW, pre-existing, not blocking). The out-dir guard compares path strings, so a path alias into the checkout gets through

Task `qe-fix-ABC-204`. Evidence: cases c8 and c9 in `<scratchpad>/qe204fix/probe-results.txt` (see this task's proof observation).

- **What:** the guard tests `real === REPO || real.startsWith(REPO + sep)` on `realpathSync` output. Node's JS `realpathSync` resolves symlinks only. On this host's case-insensitive APFS, two kinds of alias get through at both `16c51d1c` and `64f29cdd`, and both name a directory inside the checkout:
  - a **case-variant spelling** of the checkout path;
  - the **`/System/Volumes/Data` firmlink prefix** on the checkout path.

  Each probe was seeded, so each stopped at `is not empty` and wrote nothing. An empty target would get the same write-inside-the-checkout outcome that QE-204-a recorded for a symlink.
- **Why LOW and not blocking:**
  - the out dir is caller-supplied, and the guard is not a security boundary (as in QE-204-a);
  - getting through needs a deliberately odd spelling of the path;
  - the behaviour is the same at base, so the fix did not cause it;
  - it does not touch play or the readings.
- **Fix options, measured on this host:**
  - `realpathSync.native` canonicalises the case variant to the checkout path, but it leaves the firmlink prefix in place.
  - Comparing `dev`/`ino` of `out` and each of its ancestors with `REPO`'s `statSync` closes both aliases.
- **Route:** the Orchestrator's call. It could ride any later `tools/rating/` hop, and it does not need to come before ABC-205's D reading.
