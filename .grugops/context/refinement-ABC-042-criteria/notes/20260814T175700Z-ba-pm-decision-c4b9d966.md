# The `ABC-041` defect class, twice on one page — and why BOTH were closed by DELETING, not re-wording

The class, in this project's own words: **a criterion whose literal reading rejects the delivered build.**
`ABC-041`'s lesson, from its `A4`: when a criterion's stated **purpose** is false, **delete the false
clause rather than re-word it**, and move any surviving property to a new, honestly-scoped criterion
(`A4` → `A11` there). Re-wording preserves the sentence's authority while quietly changing what it claims;
deletion forces the surviving property to be re-stated where it is true.

## Instance 1 — security bar 1 vs `A1`. Closed by a SCOPE ruling, not by me.

Raised by the Orchestrator as a `claim`; **ruled by Security/NFR** (`…decision-592c0a9e`): "the delivered
diff" in bars 1 and 3 and in the builtin clause means **the delivered PRODUCTION modules**. My repair is
`RF-5`: write that scope onto the page and add `BAR 1b` so the one file that may spawn is governed rather
than merely exempt. **Nothing was deleted here** — the clause was not false, its *scope* was unstated, and
a ruling on scope is the honest fix. Deleting bar 1 would have removed a real control.

**The discriminator between the two instances, stated so the lesson is not over-applied:** bar 1 was
**under-specified** (true of production, silent about tests). `A10`'s clause was **false** (it forbade an
edit the same criterion required). Under-specification is repaired by stating the scope; falsity is
repaired by deletion.

## Instance 2 — `A10`'s two halves, found by the census, not by the claim.

`A10`, as worded, required `src/` to be **byte-identical** apart from the two new modules' own files —
while `A10`'s **own** "Suite green, skip 0" could not be met without editing `src/history-pane.nfr.test.ts`
(`LICENSED_DRIVERS` must gain the entry point, measured out of tree by Architect/Design: the correct flat
build fails `expected [ 'turn-loop.ts' ] to deeply equal [ 'cli.ts', 'turn-loop.ts' ]`).

**What I deleted:** the file-list's "and nothing else" and "`src/` otherwise byte-identical" — from `A10`.

**Why they were false rather than merely narrow:** `A10`'s stated purpose is *"the reserved distribution
decision is measurably unmade"*. Byte-identity of `src/` does not serve that purpose at all — the
`package.json` key-by-key assertion is the whole of it. The byte-identity clause had drifted in as a
general tidiness fence, and as a fence it was **factually wrong about the delivered build**. That is the
`ABC-041` shape exactly: a clause whose stated reason does not hold.

**What survived, and where it went:** the real property — *no merged code is quietly changed to make this
ticket pass* — is genuine and worth keeping. It is now **`A12`**, scoped honestly:

- the diff's file list, **naming `src/history-pane.nfr.test.ts` as expected**;
- **all 18 merged PRODUCTION modules byte-identical** (the property that actually matters — production
  cannot be edited to make the build pass);
- the one permitted merged-file change bounded to **one array element plus its citation line**;
- suite green, skip 0 — now compatible with the file list instead of contradicting it.

**A weaker repair I refused:** widening `A10`'s file list to "…and any test file the build requires".
That is *"amend the rule to match what shipped"* — it would admit any merged test-file edit, which is
precisely the hole `A12`'s one-element bound closes.

**A repair I did NOT make, and why:** I did not delete the "Suite green, skip 0" clause. It is true, it is
the thing that *forces* the licence entry, and moving it beside the licence bound in `A12` makes the
dependency visible to the engineer instead of leaving it as a trap.
