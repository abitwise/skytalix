## Why PASS_WITH_RISKS and not PASS

**Four wrong builds passed the delivered net 672/672** — `QS2`, `QS3`, `QS4`, `QS6`, all one class:
a build that is wrong only where a **qualifier and a check/mate suffix appear on the same string**.
Zero of the repository's 111 hand-typed rows carried both, and the 207-position corpus contains 32
qualified checks and **zero** qualified mates. They are closed at this hop by
`src/san.suffix.hardening.test.ts` (5 positions, 11 rows, 4 tests, 6 ms) and all four now die. The
measurement, the harness discipline and the external-oracle confirmation are in the `observation`
note beside this one.

That is a PASS on the ticket's own terms — `ABC-025` asked for the 44 census cells and got them, and
its criteria kill everything they were written to kill. It is not a clean PASS because the ticket
shipped a net with a measured hole in it and because `N5` leaves this gate breached and unresolved.

## Why not FAIL

**No row proved the delivered code wrong.** `src/san.ts` answered every one of the 11 new strings
correctly, confirmed against `chess.js@1.4.0` outside the repository (0 disputed, 0 mismatches over
115 moves). `A6` therefore does not fail by design, no defect ticket is owed, and nothing about the
delivered module changed.

## The brief's four questions, answered on my own instrument

1. **Are the four behaviour-equivalent controls still alive?** **Yes.** `Q22`, `Q24`, `Q29`, `Q40`
   survive 672/672 before this hop's rows and **676/676 after them** — killed count still zero. I
   added five equivalence controls of my own; `EQ3`, `EQ4`, `EQ5` also survive. `EQ1` and `EQ2` are
   killed, and **only** by `san.nfr.test.ts`'s `N1` call-count rows, which exist to pin the
   generation count. No behaviour row anywhere kills an equivalent mutant.
2. **Can `A2`'s census pass vacuously?** **No — and the guard is not the one it looks like.** The
   `44 of 44` assertion alone WOULD pass on a shrunken grid: `REACHABLE_CELLS.length` is never
   asserted to be 44, so a grid that lost a piece type would report `32 of 32` and be green.
   Measured by mutating the test file out of tree: dropping `["B", BISHOP]` from `CELL_TYPES` leaves
   the `44 of 44` row and the rook-square row GREEN and is caught by the **leave-one-out** row alone
   (the bishop ladders stop being load-bearing). So `A2` is non-vacuous as delivered, on one row's
   shoulders. Carried as a risk rather than edited — it is not a wrong-build hole.
3. **Did `A1` read the qualifier out of the emitted string, or ask the module?** **Out of the
   string, and it is a search rather than a second copy of the procedure.** `minimalQualifier` walks
   `["", file, rank, square]` and returns the first entry admitting exactly one same-byte mover;
   `src/san.ts` accumulates two flags. Different formulation, same rule — which is what `## Test
   notes` 2 asks for. `qualifierOf` strips `+`/`#`, the piece letter, the destination and a
   preceding `x`; `toSan` is the only import, so `A20`'s one-export surface is not widened. One
   consequence, measured: the reader's `slice(1, -2)` is **blind to the piece letter itself** —
   `T08` (the king's letter lower-cased) leaves `A1` green and dies on `ABC-013`'s `A2` row and the
   shape property instead.
4. **`A6` re-checked.** `md5 -q src/san.ts` = **`cbcc3be37c21414d16e8e6b4d0c68959`**, unchanged.
   `git diff --numstat main -- src/` = one tracked file at **655/0** plus this hop's new untracked
   `*.test.ts`; **zero deletion lines** under `src/`; the same diff restricted to every pre-existing
   `src/` file is **EMPTY**; `src/san.qualifier.hardening.test.ts` is **byte-identical** to its
