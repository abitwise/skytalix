## Consumers of `clause-b.mjs` output
`git grep` for `clause-b`, and for `(b1)` outside markdown and recorded outputs, at the tip.
- **No live gate parses it.** `src/`, `tools/`, `scripts`, `package.json` and `.claude/` hold 0 references. The
  `clause (b)` hits in `src/book.ts` and `src/book.test.ts` are prose comments. Security/NFR and the Orchestrator read
  the output by eye. The `limb N:` verdict line's form is unchanged.
- **The by-hand recipe** (`secnfr-ABC-101/probe/ruling2-by-hand.out.txt`) pipes `| grep baseline`. That line is
  unchanged.
- **Four probe harnesses** were run here with OLD and NEW at `dc4d4f15`, in `git clone --shared` copies under the
  scratchpad:
  - `design-ABC-072/probe/mutants.sh` (9 plants), `design-F-072-1/probe/f-mutants.sh` (10) and
    `secnfr-ABC-072/probe/sec-mutants.sh` (13) use `grep '(b1)' | sed 's/.*: //'`. On limb 1 that now matches the
    Ruling 2 line too, so **all 32 limb-1 rows split across two lines** (`b1=0` / `1 b2=0 …`). This is a display break
    only: their verdict column reads `^  limb`.
  - **Limb sets change on 3 plants, by design.** F5, F6 and S10 go from `L3` to `L1 L3`. Each base holds a limb-1
    `child_process` import and the head edits another line of that file, so Ruling 2 fires (b1 = 0, Ruling 2 = 1).
    Clause (b)'s verdict is unchanged on all 23 `=>` lines, and `mutants.sh`'s 27 verdicts are identical.
  - `design-F-072-1/probe/fixtures.sh` gains one `(b1) Ruling 2 …` field in every limb-1 summary, so an OLD/NEW
    compare now differs on limb 1 for all 8 pairs while the verdicts are equal.
- **Recorded readings do not change meaning.** Every recorded `RUN.txt` / `*.out.txt` was taken with an earlier
  instrument. Those readings reproduce from `git show 341da4c1:<instrument>`, or from `design-ABC-072/probe/clause-b.mjs`
  for ABC-072's. The SE's leftover (`…83110c81`, "older probe scripts grepping `(b1)`") is confirmed, and it goes
  further: limb-1 *verdicts* change on 3 harness plants, not only the row format.
