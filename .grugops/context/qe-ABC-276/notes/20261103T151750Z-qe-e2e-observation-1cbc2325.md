  - Two more mutants are equivalent: M6 (a raw `cmd.txt` write, which the seal step redacts anyway) and M4 (a recursive `topFiles`; an r/d out dir has no subdirs but the clones).
  - **Why LOW:** today the code is right, which is proven by QE's 10 real runs. The exposure is a future refactor that drops the call. The next QE r/d reading's grep (test note 4) is a second net.

- **QE-276-b. LOW. Inherited from rpair (`ABC-225`, `pair.ts` `redact`). Owner: BA/PM (an optional follow-up), then SE.** The word pass is a plain whole-word replace. QE probed it directly:
  - **Clashing names, r/d's double pass.** A user or host named like a placeholder word (`home`, `repo`, `out`, `node`, `stockfish`, `user`, `host`) turns placeholders and labels into `<<user>>` / `<<host>>`. For example:
    - user `home` gives `<<user>>/.x`;
    - user `node` turns machine.txt's `node:` label into `<user>:`;
    - host `stockfish` turns `<stockfish>` into `<<host>>`;
    - user `user` gives `<user>` on the first pass and `<<user>>` on r/d's second.
    - A host named `skytalix` would rewrite the engine names in the PGN, which would break a later reading of the committed PGN.
  - **Short names.** A user or host name shorter than 3 characters is not redacted at all (`ab@pc` stays). A1's "0 occurrences of the user or host name" therefore holds only for names of 3 or more characters.
  - **Why LOW:** none of this applies on this host (user and host are both longer than 3 characters and clash with no placeholder). No path leaks in any case, and the sums stay right because they are taken after the last pass.
  - **Possible fix:** skip matches that sit inside `<…>`, and refuse or flag (not skip) names under 3 characters.
