# qe-ABC-247 findings: none blocking. Five INFO, no HIGH, MEDIUM or LOW

- **QE-247-a, INFO, QE harness.** The first reading of run B counted 83 skytalix moves at 4.0 s instead of 84.
  - Cause: the last move of a game carries one comment holding both the clock and the result (`{+M1/9 4.0s, White mates}`). The first reader's regex wanted the clock at the end of the comment.
  - QE fixed `probe-read.mjs` after run B and before reading H. Clocks are now matched before `,` or the end. The fix is marked in the script header.
  - B was re-read: 84. No criterion changed. The miss could only have hidden a move; it could not have added one.
  - The engine's own `info … time` lines (84 / 125 / 95) agree with the fixed counts.
- **QE-247-b, INFO, records.** By design, the dry-run print keeps the out-dir as given (`rating.ts` `hostPaths`: "out-dir as given").
  - With an out-dir under the session scratchpad, the path carries the host user name. QE redacted its committed copies with `sed`. The SE's committed prints show `<scratch>`, which was also done by hand.
  - For the batch's PREREG: redact any dry-run print before committing it. The tool's own records under `<out>` are already redacted (`ADR-0049` d4).
- **QE-247-c, INFO, A3 completeness.** The SE's "nothing else reads `skill`" list leaves out the setoption name dispatch (`name === "skill level"`, base `:340`, head `:438`) and the head comment `:381`.
  - Both are off the `go` path. The SE's conclusion stands.
- **QE-247-d, INFO, method.** QE built the probe engines with `git archive` + a `node_modules` symlink + `npm run build`. That is the `qe-EPIC-010-m1-batch` probe method. The tool's own build is `git clone` + `npm ci` + `npm run build`.
  - The lock files are equal and the compiler is the same, so the `dist/` is expected to be the same. QE did not compare it byte for byte with a tool-built clone (`UNKNOWN - verify`, low stakes).
  - The batch builds its own clones and records `artifacts.txt`.
- **QE-247-e, INFO, head SHA.** The head was built from the branch tip `cec9c252`, not the ticket's `72a65fb7`. The two differ only in `src/levels.test.ts` (ABC-245, test-only), so the head engine is the same.
  - The batch's PREREG names its own head.
