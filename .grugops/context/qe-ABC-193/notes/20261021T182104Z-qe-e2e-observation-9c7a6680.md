# ABC-193 QE re-plants and own routes: nine own config/env routes leave head byte-identical to route-off while base goes blind; quoted names dispute; R-193-a is a false dispute on the safe side only; two name/parse blind spots predate the ticket (QE-193-a, QE-193-b)

All runs used my own scratch clones (`git clone --shared` of my worktree) with a private `HOME`/`TMPDIR`/`GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM=1`. Each route was set in the clone's own `.git`, in my private global file, or in one run's environment. Each was removed afterwards, and `git config --local --get-regexp '^(color|diff)\.'` printed nothing at the end. Everything ran at `f33eb318` and again at `0222d54d`, with the same results.

**Names with a space: a blind spot on head and base** (`QE-193-a`).
- For a name holding a space, git appends a TAB to the `---`/`+++` header. Here: `+++ b/src/q t.ts\t`.
- `changedLines` keeps that TAB, so `isProduction` refuses the file.
- `N4` (a new, unreached `src/q t.ts` with `node:fs`): limbs 1 and 3 do not fire, on head and on base.
- `N5` (base: `src/cli.ts` imports a benign `./q t.ts`; head: that file gains `node:fs` + `fetch`): limbs 1 and 3 do not fire, on head and on base.
- The waiver form's `--name-only` prints `src/q t.ts` with no TAB, so the waiver half does see it.

**R-193-a, probed.**
- `RA-minus`: base gives `src/fen.ts` a template literal holding a line `-- "quoted" note`, and head deletes only that line. The diff prints `--- "quoted" note`.
- `RA-plus`: head adds a template line `++ "quoted" note`.
- On both plants, head FIRES (disputed) on limbs 1, 2 and 3, with `"quoted" note (C-quoted by git; not read)`. Base does not fire.
- Head against the no-(c) copy on `RA-minus` differs, on each limb, only by the two dispute lines and the verdict line.
- So the false dispute is real, and it only ever adds an unresolved item: the safe side. Today `src/` holds 0 lines starting `-- ` or `++ ` (`grep -rnE '^(\+\+|--) ' src` = 0).

**R-193-a's pre-existing sibling is NOT on the safe side** (`QE-193-b`).
- The header parse that R-193-a's rule sits beside reads any line starting `+++ ` as a header.
- So an ADDED line whose text starts `++ ` sets `file` to null, and every later hunk of that file is unseen.
- `PP`: head adds `++ n;` near the top of `src/fen.ts`, and in a later hunk a `fetch` call and a `process.env` read. Limbs 2 and 3 do not fire, on head and on base. `PP-ctl` is the same plant with `n++;`, and both limbs FIRE on both.
- `PP3`: the same with the `++ ` line inside a template literal. It is lint-clean (`biome check` rc 0). Limb 3 does not fire on head, base or the no-(c) copy, and `PP3-ctl` (the same plant without `++ `) FIRES.
- Limb 1 is held by Ruling 2 whenever the file holds limb 1, because the file enters `added` on its first hunk.
- The `-- ` sibling only undercounts. `PM`: a holder loses `-- m;` and, in a later hunk, a tail line. Ruling 2 reads `0 + lines, 1 - line` where 2 lines were removed, but it still FIRES.
