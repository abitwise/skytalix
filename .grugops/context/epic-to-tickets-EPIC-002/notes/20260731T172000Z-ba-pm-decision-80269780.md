# The board re-sequenced against the directive — one priority changed, ten deliberately not

The instruction I held myself to: *a re-prioritisation that moves everything is not a judgment, it
is a reflex.* So this note states what moved **and** what did not, with one line each. The
"did not" list is longer and it is the more load-bearing half.

## Changed — three entries, and only three

| Ticket | Change | The one line |
|---|---|---|
| **`ABC-020`** | **cut**, `M`, **`P0`**, straight to `Ready` | A legal position reached by legal play produces ½-½ where FIDE says 1-0, systematically against the human — the directive's clearest case, and it has a close deadline in `ABC-019`/`ABC-016`. |
| **`ABC-021`** | **cut**, `S`, **`P1`**, `Backlog` | A right the player cannot exercise is half a rule; not `P0` because `ABC-020` alone is already fully conformant. |
| **`ABC-009`** | **`P2` → `P1`**, `Backlog` → `Ready` | `legalMoves` offers a `FLAG_CASTLE` move that is not a legal chess move and corrupts the board taking it back — the query that *defines* legality returning an illegal move is exactly the class the directive names. |

**`ABC-009`'s escalation is attributed honestly.** Its own written trigger — *"if `ABC-010` is
deferred or descoped, or if any epic begins accepting a position from outside the rules core"* — has
**not** fired, and the ticket now says so in a dated line. `ABC-010` is neither deferred nor
descoped; the only position any epic accepts is `ABC-012`'s `newGame(initialFen)`, supplied from
inside the product. What escalated it is the directive. A trigger treated as fired when it has not is
a trigger nobody trusts again, and this project has two other tickets whose sequencing depends on
triggers being read verbatim.

**Not `P0`**, and the line matters: `P0` here now means *the directive applies AND the fault is
reachable*. `ABC-009` still needs a semantically-invalid position and no path produces one today.
QE's G-6 sharpened the frequency (one `gameStatus` call is enough to make the phantom king, and the
loop calls it every ply) but frequency is not reachability.

## Deliberately NOT moved — with the reason, because "no change" is a judgment too

| Ticket / epic | Stays | Why not moved |
|---|---|---|

| **`ABC-011`** (`S`) | `P1` | `ABC-020` gives it a second and now **automatic** consumer (fivefold, 9.6.1) — a real escalation in blast radius. It still does not move, because 9.6.2 is **clock-based**: a repetition loop contains no capture and no pawn move, so the clock climbs and every game terminates at 150 plies regardless of what the key does. Under-detection costs a late draw, never a hung game. Recorded on the ticket so nobody re-derives it. |
| **`ABC-012`** (`M`) | `P0` | Four epics rest on it and it is the only supplier of the repetition substrate — the directive reinforces it and changes nothing. |

Demoting them would model the directive as "stop building the game", which it does not say. What the directive *does* set is the pull order **inside** `P0`: `ABC-020` first. |

| **`ABC-017`** (`S`) | `P2` | Already the drop-first tier. `P3` is "someday" and this sits in the epic's scope line and in its Done, so moving it there would say it is optional when the epic says it is not. |
| **All six epics** | unchanged | `EPIC-002/003/004` `P0`, `EPIC-005` `P1`, `EPIC-006` `P2`. The directive lands on tickets; the two epics that own rule conformance are already `P0`. |

## Pull order — stated, rather than encoded by inflating the scheme

`P0-P3` is the configured scheme and it has four levels, so "rules work outranks renderer work"
cannot be expressed by moving priorities without either inventing a level or demoting tickets whose
rank is correct. It is stated instead, as guidance — **the pull itself is the Orchestrator's**:

1. **`ABC-020`** — `P0` correctness, and a merge-order dependency for `ABC-019` and `ABC-016`.
2. **`ABC-012`**, **`ABC-014`** — `P0`, the product's existence.
3. **`ABC-009`**, **`ABC-011`** — `P1` rules-core defects.
4. **`ABC-013`** — `P1` renderer.

Merge order is the part that is *not* advisory: `ABC-020` before `ABC-019` and before `ABC-016`.
Both were amended today to match it; the amendments are worthless if the order reverses, and the
failure mode is the one `ABC-011`'s trigger exists to prevent — the deviation stops being a bug and
becomes an encoded assumption in a consumer's own tests.

dependency**, standing on merged `src/` alone — the exact criterion that keeps
`ABC-015`..`ABC-019` and `ABC-021` in `Backlog`. Every other column is 0. Nothing entered `Blocked`;
it stays empty.

2026-07-24. Each promotion was individually justified, so no single one was wrong. The trend is the
signal, and a buffer that fills while the column it feeds is empty is a queue, not a pipeline. Flagged
for the Factory Coach, not acted on here — throttling intake is not this subtask's call.
