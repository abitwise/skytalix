# The campaign that proves it: 20 mutants, all nine own-type admissions DIE, all nine equivalents STILL SURVIVE

## Instrument, and the two traps it was built against

Every mutant applied to a **copy** of `src/` held **outside** the repository, `node_modules`
symlinked. Each mutant asserts its anchor occurs **exactly once** in the pristine source and that the
bytes **actually changed** — otherwise `HARNESS-ERROR`, never `SURVIVED`. `npx tsc --noEmit` per
mutant so a broken build cannot be scored a legitimate survivor. `src/moves.ts` restored and
**re-hashed to `0e247853ab2c05887c76105ff83d8621` after every mutant**, and the repository's own
`src/` never mutated at any point. Both test files run per mutant with a JSON reporter, so failures
are attributed **by test name** rather than eyeballed.

**The refusal path fired, and that is worth recording rather than hiding.** On the first sweep the nine
core mutants were mis-generated by a bug in my own harness (a spread of `[fn()]` yields one element,
not two), so their anchors did not match. The harness reported **nine `HARNESS-ERROR`s and scored
nothing** — where a harness without that assertion would have reported **nine false survivors** and I
would have concluded the dimension could not be closed. Fixed, re-run, and the campaign was re-run a
third time after a lint autofix so every number is against the **delivered bytes** (`cmp`-verified
between the scratch tree's copy and the repository's file).

**One process per tree, everywhere.** BA/PM's first harm probe ran four tree states in one process and
Node's module cache served pristine `moves.ts` to every round, producing a false *"the harms don't
reproduce"*. Every vitest and tsc run here is its own OS process by construction, and the harm probe
below spawns a **fresh `node` per tree state** — pristine and mutant alike, never a loop inside one
process.

## The rows were proved NON-VACUOUS, which a 22-row table can fail silently

A row asserting *"no castle is offered"* also passes when its FEN sets up something else entirely, so a
typo makes the table **claim** a type it never tested — a sample masquerading as a quantifier one level
further down. `expectImpostorSetup` closes that, and it was falsified rather than trusted, on two
deliberate row corruptions in a scratch copy against pristine source:

```
label PAWN, FEN carrying a BISHOP — and the count 19 COINCIDES, so every OUTCOME assertion passes
  -> RED: "the impostor must stand on the square under test: 4k3/8/8/8/8/8/8/K3B2R w K - 0 1"
the matching rook deleted from the king's-square ROOK row
  -> RED: "the OTHER precondition must hold: 4k3/8/8/8/8/8/8/K3R3 w K - 0 1"
```

Without those assertions the first corruption is **invisible**: a row labelled `PAWN` testing `BISHOP`
twice, with the exhaustiveness check reading green because it reads the label.

  suite**, which is a weaker statement than "they are equivalent".
