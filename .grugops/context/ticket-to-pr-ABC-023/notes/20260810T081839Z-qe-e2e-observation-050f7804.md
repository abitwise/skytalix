# `A5` re-run on an INDEPENDENT harness: 67 mutants × three tree states — both halves hold, and the engineer's three declared limitations are ruled on with measurements rather than inherited

`A5` was asserted only by the instrument of the role that wrote the rows. That is the exact shape
`ABC-009`'s `A7` had before it was retired as false, so this hop treated `A5` as **unasserted** and
re-derived it. **The harness is mine and shares no code with the engineer's** — a different mutant
catalogue, a different runner, a different verdict rule. **Nothing below is inherited.**

## The instrument, and the traps it is built against

Every mutant is applied to a copy of `src/` held **outside** the repository with `node_modules`
symlinked. Each anchor is asserted to occur **exactly once** in the pristine source and the bytes
asserted to have **actually changed**, or the run is `HARNESS-ERROR` and never `SURVIVED`. `tsc
--noEmit` runs per mutant, so a tree that does not build is `BROKEN-BUILD` and never a legitimate
survivor. **One OS process per tree state** — every `tsc`, every `vitest` and every deep-perft probe
is its own `spawnSync`. `moves.ts` is restored from the pristine snapshot and **re-hashed to
`6335b452fc21ffe2d0f902ecab930840` before and after every single mutant**, and the repository's own
`src/` was never written by the harness (asserted at the start and end of every run).

**The instrument was verified before any red was believed.** A two-mutant smoke test ran first: one
mutant that must die (`WK kingPath drops e1`, the origin) and one that must die only because of this
ticket's rows (`WK kingPath drops g1`). Both died, naming the tests that killed them, before the
catalogue was trusted.

One mutant of my own design was found to be **unsound and is reported rather than counted as
evidence**: `S3b`, which shields the landing square from knight attacks by blanking every enemy
knight, also unblocks slider rays and so over-rejects. It died in `perft` for the wrong reason. Its
clean replacement is `S3a`, which narrows only the landing square's test.

## The engineer's three declared limitations — ruled on, each with a measurement

**1. A pair mutant conditional on BOTH axes at once survives `A1`'s four rows. → CONFIRMED, and it is
a COVERAGE GAP, not `A1`'s stated bound.** Measured: `enemy-KNIGHT pair, WHITE and QUEENSIDE only`
and `own-QUEEN pair, BLACK and KINGSIDE only` both survive 578/578 with deep 32/32. The measurement
that separates "out of scope" from "the criterion is short" is the **control**: the same mutant keyed
on `WHITE and KINGSIDE` — a combination a delivered row does carry — **dies at 577/578**. So the
class is discriminable at four extra rows; nothing about it requires enumerating the 169-combination
byte-pair space, which is the trap `## Size and priority rationale` actually names. The `L` trap is
about the 13×13 **byte** space; this is the 2×2 **axis** space, and they are different objects. The
repair is four rows, added here.

**2. One of the nine `A3` rows was already dead pre-rows (8 of 9 individually necessary). →
REPRODUCED EXACTLY, and ruled a FINE rather than a criterion shortfall.** `rook's square admits own
BISHOP only QUEENSIDE` is `KILLED 558/559` on the pre-rows tree in my harness too, the same count the
engineer reported, and I confirmed its killer is `ABC-009`'s existing `ONE_OF_TWO_RIGHTS_VALID` row.
It is a fine because `A3`'s Then-clause is a statement about **the tables' doubling**, not about each
row being the unique killer of one mutant: `IMPOSTOR_ON_ROOK_SQUARE`'s BISHOP rows really were both
kingside, the delivered quantifier test asserts that directly, and removing the row turns it red. A
criterion is short when a wrong build passes it; nothing here shows one does.

**3. The gate's terminal verdict is a `claim`, not a stamped finding. → CORRECT, and I re-derived
every gate number I rely on rather than inheriting it.** There is no `scripts/context-io.ts` in this
install and `human_admission` is `off`, so no `§14-gate#<id>` exists to reference. My own gate numbers
are in the `claim` note for this hop; each was run by me at this hop.
