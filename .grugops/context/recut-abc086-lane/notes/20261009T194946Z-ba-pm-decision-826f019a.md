# `ABC-086` `N8-LANE` re-cut: `A1` default slice 15 × 2 with a depth-2 floor, `A6` 10/10 to `ENGINE_DEEP`. Estimated ≈ 160–240 ms. DoR 10/10

Hand-authored, no seal. This install is in the degraded posture `AGENTS.md` describes, so no
`finding` is admissible. The note covers task `wave-2026-09-25`, subtask `recut-abc086-lane`
(Workflow 07), on branch `grugops/recut-abc086-lane` from the build `339f940`. The ticket page is
authoritative; this note records why it reads the way it does.

## Decision

1. **`A1`'s default-lane slice becomes 15 × 2** at the same budget: 2 virtual ms, step 1, a fresh
   `virtualClock` per run.
   - **The positions.** The `startpos`, `position-3` and `position-5` families of the shared
     `thirtyPositions()`, each root plus its first four children.
   - **The asserts.** The move is identical 30/30, **and root depth ≥ 2 on 15/15**.
   - **Why.** The floor is what keeps the guard above depth 1. These are the only three families
     where every member reaches depth 2 at budget 2, and they are also the cheapest.
   - **The 30 × 2 slice is not carried** into either lane, because the deep 300/300 covers the same
     30.
2. **`A6`'s 10/10 interleaved row moves to `ENGINE_DEEP`**, unchanged. `A6`'s per-instance
   clock-state row (about 0 ms) stays in the default lane.
3. **Unchanged:** `A1`'s 300/300 and its depth-4 floor (deep), `A2`, `A4`, `A5` and `A7`. There is
   no new criterion and no new row.
4. **Fallback (pre-measured).** Drop `position-5` to give 10 × 2, which read 92–104 ms with 10/10
   at depth 2. The Engineer may take it if the standing instrument reads between 450 and 650 ms.
   Above 650 ms is a stop, as before.

## Arithmetic (in vitest, never plain `node`)

The readings: Apple M3, Node v26.11.0, `vitest run --pool threads`, load1 4–6. The probe imports
the worktree's `src/` by absolute path, so no `src/` file was touched. It is calibrated: its 30 × 2
readings (806.9 ms summed per position; 848–1 030 ms per fresh process) bracket the build's
713–903.

- **Per position**, from one process with 2 runs each (`raw-out-perposition-build.txt`):

  | | `startpos` | `position-3` | `position-5` | `kiwipete` | `position-4` | `position-6` |
  |---|---|---|---|---|---|---|
  | kept | 56.1 ms | 25.2 ms | 63.3 ms | | | |
  | dropped | | | | 333.5 ms | 130.4 ms | 198.4 ms |

  - Kept totals **144.6 ms**. Dropped totals 662.3 ms. The sum is 806.9 ms.
  - The dropped families held 7/15 positions at depth 1: `kiwipete` ×5, `position-4/f3d4` and the
    `position-6` root.
- **Whole slice**, a fresh process per reading, conditions rotated over 5 rounds
  (`raw-out-rounds-build.txt`):
  - 15 × 2: 180 / 185 / 195 / 211 / 229, median **195 ms**;
  - 30 × 2: median 895 (848–1 030);
  - the ratio is **0.218**.
- **Scaled to the build's in-lane attribution** (`…542d743a`): 0.218 × 713–903 = **155–197 ms**.
- **The rows that stay** (`A4`, `A5` ×2, `A6` state, `A7` ×3) were each ≤ 3 ms in the build, so
  together they add ≤ ~10 ms.
- **Estimate: ≈ 160–240 ms net.**
  - The low end is 155 + ~5.
  - The high end is the worst fresh reading, 229, + 10.
  - A fresh process is cold, so the estimate errs high.
  - It sits under the brief's ~450 ms target and under the 650 ms bar.
  - It stays `UNKNOWN - verify` until the standing instrument reads it.

## Facts corrected or added

- **The brief says the default slice is "30 × 2 at budget 24". It is budget 2**
  (`src/engine.test.ts`, `nonIdentical(2, 2)`). 24 is the deep row's budget. The page states it
  correctly.
- **The wave-tip pre-read** (`1c86e9d`, with `ABC-082` merged at `3858e3c`) used an identical
  inline ticking clock, because the wave tip has no `src/virtual-clock.ts`. It is not the merged
  tree and not a pass.
  - **The 15 × 2 slice:** 15/15 reached depth 2, at 193–199 ms (`raw-out-rounds-wavetip.txt`).
  - **The deep budget of 24:** 24/30 reached depth ≥ 4 (the floor is 15, and the build tree read
    27/30), with 60/60 identical (`raw-out-b24-wavetip.txt`, `raw-out-b24-build.txt`).
  - **The old 30 × 2:** it fell to 20/30 at depth ≥ 2.
  - **So the evaluation change moves depths, as `…3bb7069b` §3 warned.** The new slice and the
    deep floor both survive it on this read.
- **The build branch is based on `1d74693`, before `ABC-082` merged.** The re-hop merges the wave
  tip and re-reads `A1` there. That is on the page under Dependencies and Delivery.
