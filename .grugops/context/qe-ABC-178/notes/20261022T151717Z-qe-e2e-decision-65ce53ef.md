# QE ruling on the SE's B3 flag: the one blank separator line is **inside "additive only"**. B3 is MET

**The flag** (SE `…82e891e8`). The hunk adds 7 lines: 1 comment, 5 lines of R1, and 1 blank separator. The re-ruled B3 reads: "every hunk adds only R1 and comment lines citing `ABC-178` or `QE-177-a`. One file, no `-` line." A blank line is neither a comment nor code.

**Ruling: the blank line is part of R1's row, so B3 is MET.**
- **B3 guards two things.** No existing line changes, and nothing but R1 enters the file. Both hold. `-U0` shows 0 `-` lines. `--name-only` lists the one file.
- **A blank line carries no token and no behaviour.** It cannot hide scope. No test, lint rule or mutant can tell the file with it from the file without it, except by line numbers.
- **It is the file's own style.** In `src/uci-session.test.ts` at the tip, all 40 `it(` blocks that follow a closing `});` are separated from it by one blank line. There are 0 adjacent ones. Without the blank line, R1 would be the file's only exception. AGENTS.md coding rule 11 asks for matching the existing style.
- **Git's hunk boundaries are arbitrary here.** The same blank line could be shown before the comment or after the row. Which one it is says nothing about scope.
- `npx biome format` accepts the file as is (exit 0).

**What would change the ruling:** a blank line that splits or moves an existing line, or a hunk elsewhere in the file. Neither exists.

This is a QE reading of the page's words, not a re-cut. BA/PM may re-read B3 if it meant "no whitespace lines at all". QE sees no reason to send it back.
