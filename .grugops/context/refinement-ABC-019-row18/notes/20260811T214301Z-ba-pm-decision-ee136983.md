# The two flags ruled, the cl. 9f discharge recorded, and the board move I did not request

> **Hand-authored** — `scripts/context-io.ts` does not exist here. `kind: decision` needs no stamp;
> the measurements these rest on are in the sibling `observation` note, and **nothing at this hop is
> recorded as a `finding`, because the gate is RED and there is no verdict to stamp against.**

## 1. Flag 1 — row 18's Expected was stale in every clause. REPAIRED (`[D53]`)

The Engineer was right to flag it and right not to take it. The cell read *"**BLOCKED on `ABC-027`**:
RED until it merges, and written at the rebase with `ADR-0009` cl. 9f's real-panel re-gate — not
before"*. `ABC-027` is merged, the rebase is done, `A20` is written and green.

**Why this is a defect and not untidiness:** the Expected column is what a reader consults to know
what the row is *supposed* to do. One that names a block which no longer exists tells the next reader
the row is meant to be RED — and this ticket has produced that exact defect four times already
(`[D21]`, four stale status statements copied into a ticket).

**The repair form is a RECORD plus a CHECK, never a fresh status**, on this ticket's own precedent
(`[D51]`'s *"a panel is unmerged exactly while its module is absent from merged `src/`"*). The cell
now states the screen property, states the assertion that keeps it non-vacuous, and dates the block
as spent; the check it hands forward is **"this row is blocked exactly while this cell names a ticket
it waits on"**, which cannot go stale the way a status does.

**Two sibling sentences carried the same spent fact and are dated with it**, because repairing one of
three would have left the ticket contradicting itself: the `## Test notes` intro's *"and it is the
only one blocked on another ticket"*, and the `## Dependencies` `ABC-027` bullet's instruction
*"written at the rebase … not before"*. **`A20`'s own note in `## Acceptance` was deliberately NOT
touched** — *"cannot be satisfied until `ABC-027` merges … RED by design before it and GREEN after
it"* is a conditional, it is self-dating, and it is the reason the assertion was not written earlier.
Editing it would replace a durable sentence with a perishable one.

## 2. Flag 2 — the real panel replaces the prescribed stub. RATIFIED (`[D54]`)

**Ruled, not rubber-stamped.** `## Test notes` prescribed *"a stub whose status panel's widest row
shrinks between two frames is the shape"*. The Engineer used the real panel. I uphold the
substitution, and **the prescribing sentence is what changes — not the test.**

**The Engineer's own argument checks out but is not airtight, and I say so rather than adopt it
whole.** It argued that a third stub seam would contradict `A18`'s *"there are **two**"* — verified at
source, `A18` reads exactly that, so that route does require amending a criterion to satisfy a
criterion, which this ticket has refused five times. **But it is not the only stub route.** `A20`'s
own note already observes that *"a stub whose panel rows vary in width varies no row count"*, so the
shared `statusStub` could have been made width-varying without adding a seam. **That route costs
something else: it changes the fixture all 14 table rows drive through for one row's benefit**, which
is precisely the mistake `[D43]` split rows 3 and 16 to stop making. So both stub routes cost a real
thing and the ratification does not depend on the third-seam argument alone.

**What decides it is evidence quality, and that is the ground I rule on.** A stub narrowing proves
the criterion fires at a narrowing someone invented. The real claim cell proves `ADR-0010`'s measured
defect — `material: 0` rendered as `material: 01`, an expired draw claim left on screen — is
**reachable in the composition this project ships**. `A20` exists to check exactly that, and no stub
can supply it. The prescribing sentence was written at the fourth hop when **neither panel was in
merged `src/`**, so it encoded the tree's state and not a property of the criterion; both panels
merged before the rebase and its reason expired.

**Three boundaries hold under the ratification and I checked each rather than assuming:** the
narrowing is still a **panel** row (the bullet's load-bearing clause, and the run carries no message
item at all); `[D47]`'s width prohibition is untouched — `W` varies **45/22/23/27/24**, the opposite
of a constant-width claim; and `A18`/`A19` are unamended with both stub shapes still running.

**THE COST IS REAL AND IS RECORDED, NOT ABSORBED.** `A20`'s evidence now depends on
`src/status-panel.ts` keeping a claim cell that appears and disappears. The mitigation is the
Engineer's and it is the right one: the test **asserts the narrowing exists**
(`src/turn-loop.test.ts:1431-1437`) and fails loudly rather than passing vacuously — and vacuity is
the exact failure that bullet was written to prevent, so the delivered fixture serves the bullet's
purpose better than the bullet's own prescription did. **That assertion is now part of row 18's
Expected and must not be removed as redundant**, and the coupling is flagged at `ABC-016`'s door
(flag 23) without opening that ticket.

## 3. The cl. 9f check — the discharge was NOT recorded, and now is (`[D55]`)

**The check's answer is NO.** Cl. 9f is discharged in full — both panels real, measured — but the
ticket still read as though the obligation were open: `[D51]` (1) said *"the obligation is NOT closed
until `ABC-017` is merged too"* and demanded that whoever ran the re-gate **state WHICH panels were
real**. That sentence existed only in the Engineer's context notes and in `src/turn-loop.test.ts`'s
header — **not in the ticket**, which is where a later hop reads it. **A ticket that still says an
obligation is outstanding after it is met is `[D21]`'s defect arriving from the other direction.**

**The two places are derived, not assumed.** Grepping every `9f` mention, the obligation as an
*instruction to a rebase hop* lives in exactly two: `## Dependencies` (`[C9-4]`'s *"the re-gate must
run this loop's tests against the REAL panels"* plus `[D51]`) and `## Test notes` (row 18's Expected).
`## Acceptance`'s `A20` note is a third mention but it **cross-references** `## Dependencies` rather
than carrying the obligation. Both places now carry the discharge, and `HISTORY_ROWS = 8`'s
`UNKNOWN - verify` is retired by measurement.

**Not re-opened:** `ADR-0009` and `ADR-0010` were not opened for edit and neither is re-opened. The
discharge is recorded **in the ticket**; whether the ADR wants its own record is Architect/Design's.

## 4. Size `L` (5) and priority `P0` — re-derived a SEVENTH time, both UNMOVED

The standing tripwire asks a hop *adding production scope* to test `SPLIT_REQUIRED` rather than lean
on precedent. **This hop adds none — zero production, zero test.** No criterion added, amended,
renumbered or deleted (**27**, `A1`–`A20`), the table stays **18 rows**, `src/` was not opened, and
`N8-LANE` cannot move because zero test files were added. The largest ruling **ratifies what was
already built** rather than commissioning anything.

`SPLIT_REQUIRED` was still tested against the honest question — *is a second ticket hiding here?* The
answer is the sixth hop's and it has not changed: **yes, and it is already `ABC-029`**, with
`ABC-028` before it. The only candidate this hop could have created is *"re-fixture `A20` against a
stub"*, and that is not a ticket: no user, no value independent of this loop, no artifact, and it
would spend a hop to make the evidence **weaker**.

`P0` holds. Two discharged holds move **readiness, not value** — the same distinction the fifth hop
drew for `ABC-016`'s merge.
