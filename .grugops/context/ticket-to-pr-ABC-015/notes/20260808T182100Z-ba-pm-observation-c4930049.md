## Two things checked that turned out to be fine, recorded so nobody re-checks them

- **The positive `LANG` path is covered, so no criterion is owed for it.** There is no bullet for
  "no flag, TTY, `LC_ALL`/`LC_CTYPE` unset, `LANG=en_US.UTF-8` → unicode", which is the commonest
  real case on Linux and macOS. It is not a hole: an implementation that ignores `LANG` entirely
  dies on the `LANG=en_US.ISO-8859-1` bullet, and the unicode answer is also the default, so the
  positive case can only be reached by a rule that already reads `LANG`. **Adding a criterion for it
  would be decoration.**
