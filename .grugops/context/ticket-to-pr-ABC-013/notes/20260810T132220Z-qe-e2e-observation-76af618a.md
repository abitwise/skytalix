# An EXTERNAL oracle was available after all — `chess.js@1.4.0` disputes NONE of the expected strings, and `src/san.ts` matched it on 649,556 SAN strings with zero mismatches

This is the answer to the question three hops in a row recorded as open. BA/PM: *"Nothing in this
repository or this session was checked against an external SAN implementation, a PGN corpus, or the
FIDE/PGN specification text. **There is no such oracle here.**"* The Engineer: *"No external
instrument was consulted … this repository contains none and I added no dependency."* The
Orchestrator: *"I verified the positions; I did not verify the notation."*

**The premise was wrong, and it was worth re-checking rather than inheriting.** This machine has
network access. An external implementation of the same grammar was one command away.

## What was installed, and where it is NOT

`chess.js@1.4.0`, installed with `npm install` run **with this session's scratchpad as the working
directory**, outside the repository. Checked afterwards, not assumed:

```
git status --short           →  only .grugops/queue/claimed/ (this hop's own claim)
git diff --stat -- package.json package-lock.json   →  EMPTY
node_modules/ in the repo    →  no chess.js, no pgn package
```

**No repository dependency was added.** `AGENTS.md` § Safety rules says do not change dependencies
without reason; the reason here would have been good, and it still was not needed — a QE instrument
does not belong in the shipped dependency set. It is scaffolding in a scratchpad, like BA/PM's and
the Engineer's harnesses, and it is not committed.

## Result 1 — the ticket's own table

**Zero of the 68 expected strings are disputed by `chess.js`.** Every row of the acceptance table
plus `A1`'s exhaustive 20-move set, read mechanically out of `src/san.test.ts` (and each one
confirmed present in the ticket text, so the instrument is scoring the ticket and not the code's
transcription of it).

That includes the four rows BA/PM named as the ones it would attack first — `Qee1`, `Q1e1`, `Ne4`,
`exd6` — and the three-queen ladder in full.

## Result 2 — the delivered build, over a wide corpus, in BOTH call forms

```
positions compared            8,435   (six perft positions expanded TWO plies, the 18 acceptance
                                       FENs, 18 hand-built black-to-move / three-rival / stalemate
                                       positions, and 24 deterministic 60-ply random walks)
SAN strings compared        649,556   (every legal move, rendered BOTH with and without `legal`)
SAN MISMATCHES                    0
positions chess.js refused        0
```

`toSan(position, move, legal)` and `toSan(position, move)` were both compared against the external
string on every move, which is `A19` re-asserted over 8,435 positions instead of 18.

## `A7`'s `Ne4` — the row the Engineer said to attack first — is UPHELD

The Engineer named this correctly as the only row where a reader could disagree with the **rule**
rather than the arithmetic: whether disambiguation is decided over LEGAL or over PSEUDO-LEGAL moves.

- `## Scope` says *"the other **legal** moves"*.
- The external implementation does the same: its ambiguity set is drawn from its legal move
  generation, so a pinned rival is not a rival.
- I reach the same answer from the PGN export-format text: *"In the case of ambiguities (multiple
  pieces of the same type **moving** to the same square)"* — a piece that cannot legally move to the
  square is not moving to it, so `Ne4` is unambiguous and takes no qualifier.

**The rule choice is right, and it is no longer resting on a grugops reading.** Recorded plainly
because it was the largest single open risk named on this ticket.

## What this does and does not settle

**Settles:** that the expected strings are not a shared hallucination of two grugops roles. Two
independent hand-derivations agreeing was corroboration; a third-party implementation with no
relationship to this project agreeing on all 68 rows and on 649,556 strings is a different class of
evidence.

**Does not settle:** `chess.js` is a widely-used implementation, **not the specification text**.
Where it and this repo could both be wrong in the same way, this check is blind. The remaining
exposure is narrow — it would have to be a corner where a popular library, this repo, and two
hand-derivations all agree and the standard differs — but it is not zero, and it is why this is an
`observation` about agreement rather than a claim of conformance.

## One place the external oracle is WRONG and this repo is right

On four synthetic FENs whose castling field the board contradicts — a **white king on `e8`** still
carrying the `K` right — `chess.js` offers `e8g8 O-O+`: it castles from wherever the king stands.
This repo refuses, because `ABC-009`'s identity guard reads the two home squares before offering the
move.

The repo is correct by the standard, it is move GENERATION rather than SAN, no SAN comparison was
affected, and it is an incidental independent confirmation that `ABC-009`'s guard does what its
ticket says. Recorded rather than dropped, because "the external oracle disagreed" is a sentence
that must never appear without its direction.
