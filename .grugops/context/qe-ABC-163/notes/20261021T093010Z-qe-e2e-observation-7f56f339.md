# ABC-163 QE edge plants: holder only at head, only at base, renames, and deletion-only edits; the fold is narrower than the by-hand check it retires

Plants on tree A (`git archive dc4d4f15`, scratch, outside the repository), each read with OLD (`341da4c1`) and NEW
(`87d3897d`), limbs 1–3. Limbs 2 and 3 are byte-identical OLD vs NEW on every row (14 plants × 2 limbs = 28 of 28).
"By-hand" is `ADR-0036` § S1's recipe, `git diff --name-only --no-renames <base> <head> -- <holders at base ∪ head>`.

| plant | edit | OLD L1 | NEW L1 | NEW Ruling 2 | by-hand |
|---|---|---|---|---|---|
| head-only | `src/book.ts` gains `import { readFileSync as _r } from "node:fs";` | FIRES (b1) | FIRES | `src/book.ts … holds limb 1 at <head>` | fires |
| head-only + body | the same plus a `readFileSync("/etc/passwd")` export | FIRES (b1) | FIRES | `src/book.ts (3 + lines; at <head>)` | fires |
| base-only (SE's X1, re-planted) | `book-file.ts` drops its `node:fs` import and returns `new Uint8Array(0)` | does not fire | **FIRES** | `src/book-file.ts (1 + line; holds limb 1 at <base>)` | fires |
| rename | `book-file.ts` → `book-reader.ts`, bytes unchanged; `cli.ts` import follows | FIRES (b1, b2) | FIRES | `src/book-reader.ts (17 + lines; at <head>)` | fires (old path) |
| rename + edit | the same, and the read becomes `/etc/passwd` | FIRES (b1, b2) | FIRES | as above | fires |

| uncomment (2 commits) | base: `src/book.ts` starts `/*` / `import { readFileSync } from "node:fs";` / `*/`; head: the two delimiter lines deleted, nothing added | does not fire | **does not fire** | `holders 1 at <base>, 2 at <head>; … 0` | **fires** (`src/book.ts`) |

**What Ruling 2 says on a rename.** Its unit is a `+` line of `git diff -U0 --no-renames`, so a rename is a deletion of
the old path and an addition of the new one. The new path's every line is `+`, and it fires if it holds limb 1 at
`<head>`. The instrument does exactly that. A rename that keeps the import already fired under OLD by (b1) and (b2), so
Ruling 2 adds no new fire there. A rename that drops the import holds limb 1 at neither end under the new path. The old
path has no `+` line, so neither the ruling nor the instrument fires. That is the safe direction: the capability is gone,
and any new reach from the new file is a new (b2) edge, since a new file's edges are all new.

**Deletion-only edits (QE gap G-1, G-2).** The ruling's words are "a `+` line", and the SE's decision note
(`…78d30164`) states that a deletion-only hunk does not fire. The instrument matches the words. The by-hand recipe,
which `ADR-0036` § S1 now calls "no longer needed", used `--name-only` and fired on all 4 deletion-only plants above.
- **Guard drop** is the page's own class: a holder changes what it reads, and nothing fires. It is latent. Today's
  holder is one single-line read, so no deletion-only edit can widen it. It becomes live at the first holder with a
  guard or a multi-line read expression.
- **Uncomment** turns a comment into a counted occurrence without a `+` line. It is a blind spot of the delta (b1) test
  itself, on every limb, and it predates `ABC-163`. Only the STATE line (`1` → `2` holders) shows the change, and that
  line is not a trigger.
