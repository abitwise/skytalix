# Three things this review could NOT settle — none of them blocks ABC-020, all three need somebody else's ruling

The review verdict is PASS and none of these is a reason to hold it. Each is recorded as a `claim`
with `confidence: UNKNOWN - verify` because each turns on a judgment QE does not own — a reading of
the Laws, a product choice, or an ADR seam.

## 1. FIDE 9.6.1 says "five **consecutive** alternate moves"; the code counts five occurrences

`ABC-020`'s `## Scope` states the automatic thresholds as *"five occurrences and 150 plies"*, and
`A3` is written as *"a counts map in which the current position's key has occurred five times"*.
**The implementation does exactly that, so this is not a defect against the ticket** — it is a
question about what the ticket specified.

My reading of Article 9.6.1 is that it draws the game when the same position has appeared *"for at
least five consecutive alternate moves by each player"*, where 9.2's threefold claim carries no
consecutiveness requirement at all. If that reading is right, then **five NON-consecutive
occurrences draw automatically here where FIDE would leave only the 9.2 claim** — the same error
direction as G-1 (an automatic draw taken from the player having the move), at a far rarer trigger.
It is reachable in ordinary play: a position recurring three times early, the claim declined, the
game moving on, and the position recurring twice more.

**Marked `UNKNOWN - verify` deliberately.** I do not have the Laws text to hand in this session, the
phrase is genuinely awkward, and the plain five-count is what most implementations do. I am not
willing to assert a conformance gap on a remembered sentence — that is the mistake this ticket is
correcting, not one to repeat.

**And it is not cheap to fix even if the reading is right.** A counts map carries no ordering, so
consecutiveness cannot be derived from `positionCounts` at all; it needs the per-ply key array that
`ADR-0002` clause 3 gives `EPIC-004`'s search. That makes it an `ADR-0002` / `ABC-012` shape
question, not a `src/gameend.ts` edit.

**Recommendation: a BA/PM ruling, and a ticket only if the ruling goes that way.** Do not attach it
to `ABC-020`.

## 2. `GameResult` is dead, keeping it was RIGHT, and the trap it leaves is one line to close

`export type GameResult` is referenced by nothing anywhere in `src/` — I grepped; the only
occurrence is its own declaration. The Engineer flagged it and kept it.

**Keeping it was the correct call and I would not have it deleted in this ticket.** The ratified
shape block spells `GameResult` out verbatim as its first line; deleting a line of a ratified shape
during implementation is exactly the silent substitution the design hop exists to prevent, and
coding rule 12's two halves genuinely pull opposite ways here. Flagging beat tidying.

**The trap, named so it is not discovered later.** `GameResult` is now a flat four-member union that
no longer corresponds to either arm of `GameStatus`. It is not wrong, but it readmits — in one
convenient alias — the modelling the two-arm union exists to forbid: a variable that holds `"draw"`
and `"in-progress"` with no `reason` and no `claimable` attached to either. The next author writing
`function render(result: GameResult)` gets a signature that compiles, that `GameStatus["result"]`
widens straight into, and that quietly loses the claim. That is how G-1 was expressible in the first
place.

**Cheapest close, and it is not a deletion:** `export type GameResult = GameStatus["result"];`. It
stays exported, it is byte-compatible with the ratified literal union, and it can never drift from
the arms. A doc comment saying "retained for the `ADR-0002` seam; do not use it to type a status"
would do almost as well.

**Recommendation: a one-line follow-up for whoever owns the `ADR-0002` seam (Architect/Design).**
Out of scope here — the ratified block spells the literal form, and this ticket must not amend it.

## 3. When five occurrences and clock ≥ 150 both hold, the reason is always `seventy-five-move`

Measured: `occ=5, clock=150` → `{"result":"draw","reason":"seventy-five-move"}`; `occ=5, clock=149`
→ `fivefold-repetition`. Both are automatic, the **result is identical**, and only `EPIC-006`'s
result screen ever reads the reason.

FIDE would say whichever condition arose first is the operative one, which a pure function of a
position cannot know — `gameStatus(position)` has no history beyond a count. **So I left it
unpinned:** a test here would lock an arbitrary choice between two rules that both genuinely apply,
and locking an arbitrary choice is how a later correction becomes a "regression".

**Recommendation: `EPIC-006` decides what its result screen says when two automatic rules coincide;
until then the current behaviour is fine and is recorded rather than asserted.**
