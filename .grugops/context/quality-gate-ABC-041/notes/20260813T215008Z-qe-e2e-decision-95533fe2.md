# `A4`'s substitution, adjudicated by mutant. The premise is real, the substitute is NOT "strictly stronger", and its purpose clause is FALSE.

The Engineer reported `A4` unsatisfiable as worded and asserted something it called *strictly
stronger*. The premise was independently re-confirmed (`src/frame.ts:194-208`: `assembleFrame` pads
every panel row to the widest panel, and the board's 18 columns are never the widest). **The premise
being real is the only part of the substitution that survives contact with a mutant.** Three
questions were put to it; it fails two.

## 1. "Strictly stronger" is backwards as a set relation

`A4` as written rejects **every** build on this tree, including the correct one. A criterion that
rejects everything is maximally strong; nothing can be strictly stronger than it. So the build that
"the literal `A4` kills and the substitute lets through" is **the delivered build itself** — and
every other. That is not a defect in the code. It is a defect in the characterisation, and it
matters because the next reader inherits "strictly stronger" as a settled fact and stops checking.

The honest comparison is against the Engineer's own charitable repair — *"byte-identical to
`renderBoard(...)` padded to the frame's width"*. Against **that**, the delivered line is **weaker**,
which is question 2.

## 2. The line the note NAMES as the repair is CIRCULAR. Measured.

```ts
const width = (frame[0] as string).length;
expect(boardRegionOf(frame, board.length)).toEqual(board.map((row) => row.padEnd(width)));
```

`frame[0]` **is a board row**, so `width` is the board region's own width, not the frame's. The seam
and the assertion draw the number from the same place.

**Mutant `X2` — the seam appends nine blanks to every board row** (digit-free, so `A3` cannot claim
the kill). The frame inflates to 27 columns, the assertion reads 27 off row 0, and
`board.map(padEnd(27))` matches. Run with the adjacent whole-frame equality temporarily removed:
**8 passed (8)**. The named line does not catch it.

With the file intact the mutant reds at `src/render-seam.test.ts:230` — the **whole-frame equality**,
which the note describes as a "plus". **The "plus" is doing all the work; the named repair is
decorative.** That inversion is the finding.

## 3. `A4`'s stated purpose is NOT met — and cannot be met by any byte-equality

`A4`'s parenthetical and `## Test notes` row 2 both say byte-equality *"is what forbids a second board
implementation"*. It does not, and neither does the literal wording.

**Mutant `X3b` — a genuine second board implementation.** `renderBoard`'s algorithm copied into a new
`src/board-two.ts`, called by the seam; `render.ts` left holding only type-erased specifiers.

```
npm test      -> Test Files 29 passed, Tests 824 passed (824)
npm run typecheck -> exit 0
```

**824/824 green with `renderBoard` never called.** A second implementation that renders the *same
bytes* is invisible to every byte comparison — and duplication always starts byte-identical and
drifts later, which is the failure the clause exists to prevent. The Engineer's note asserts "A second
board implementation is caught." **It is not.**

The same mutant also walks through `A8`, the epic's headline — see the mutant-table note.

## The decision

**The substitution is NOT accepted on its stated reasoning.** Its aggregate effect is sound only
because of an assertion the note treats as incidental, and its purpose clause is false. The
production module as delivered is **correct** — every mutant that changes observable behaviour is
either caught or was caught once the gate added rows. What is wrong is the *account* of why it is
held, and an account is what the next six hops will build on.

**What replaces byte-equality, and it is not a comparison at all:** the merged four must be **CALLED**.
That is a call count, it is one row, and it kills `X3b`. Added to the existing file — see the
artifact-ref note.
