# `ABC-248` QE findings: ruling 6's `-t` form is vacuous (QE-248-a, MEDIUM, carrier BA/PM); P-2 leaves QPLY4 alive across the whole lane (QE-248-c, LOW, pre-existing); five INFO. None blocks

No `finding` kind is admissible on this install, so these are recorded as an observation.

## QE-248-a (MEDIUM, a gate-command trap in ruling text; confirms SE-248-a). Carrier: **BA/PM**, at `ABC-248`'s close fold
- **What the text says.**
  - Ruling 6 (ticket page § BA/PM ruling) and A10 give the command
    `ENGINE_DEEP=1 … vitest run src/uci-session.test.ts -t "<moved describe>"`.
  - `ADR-0046` § Addendum 2026-10-31, the Architect's condition 4, spells the same thing.
- **What it does.** Vitest reads `-t` as a regular expression, so the title's "[deep, ENGINE_DEEP=1]" becomes a character
  class. Written as the ruling spells it, the command prints **"Tests 241 skipped (241)" with exit 0**. That is 0 tests run,
  a vacuous green (`raw/deep/unescaped.txt`).
- **What works.** The escaped form `-t "… \[deep, ENGINE_DEEP=1\]"` prints **"4 passed"** (`raw/deep/escaped.txt`).
- **Why it matters.** A later gate that copies ruling 6 as written would pass A10 without running a row. The same trap
  holds for every `[deep, …]` describe title in the repo. `AGENTS.md`'s `-t "ABC-221 A10"` avoids it by stopping before
  the bracket.
- **Remedy (records only, no code):** BA/PM amends ruling 6 / A10 on the ticket page and in the ADR's dated ruling section.
  - Use the escaped form, or a bracket-free prefix such as `-t "line's time \[deep"`.
  - Add "check that the run prints 4 passed".
  - If Architect/Design wants condition 4's text to match, that is a co-edit, not a blocker.
  - `AGENTS.md` needs no edit. Its spelled `-t` example is already safe.
- **Why it does not block:** the delivered rows run 4/4 green in the escaped form. The fault is in the gate's text, not in
  the tree.
