# `ABC-025` CUT and promoted `Backlog` → `Ready` — DoR 10 of 10, size `M`, priority `P2`

`plans/tickets/ABC-025-san-qualifier-minimality-net.md`. Six acceptance criteria, 23 supplied
positions, 63 supplied strings, **zero production lines expected**. The measurements are in the
`observation` note beside this one and are not repeated here.

## The scoping decision, and why the ticket is not five criteria

The subject of this ticket is *criteria that failed to catch wrong builds*, so criteria that
re-state the five mutants would close five holes and leave the class open. The class was named first
and the criteria derived from it:

> **The acceptance net is asymmetric in three dimensions — piece type, colour, capture-ness — and
> every measured wrong build lives in one of the three.**

The property that closes it is the qualifier's **purpose** rather than its procedure: *the shortest
entry of the ladder `"" → file → rank → square` for which exactly one legal move of that piece byte
reaches that destination*. Then the property was checked **against** the mutants, in that order — and
that is what caught the thing this ticket turns on: **the property alone, over the corpus
`src/san.test.ts` already has, closes only three of the six.** `Q34` (bishops) and `Q38` (black on
the rank rung) survive it, because that corpus fills 5 of the 44 reachable cells. A ticket that had
said "add the minimality property" would have read as though it closed five.

Four rulings follow, each recorded so it is not re-litigated silently:

1. **The corpus richness is itself a criterion (`A2`), and it is stated that no wrong build can
   witness it.** Its witness is a narrowed corpus, and its discriminating requirement is numeric
   (removing this ticket's positions must leave ≥ 35 of 44 cells empty). This is the anti-vacuity
   guard on `A1`; without it `A1` is a property that can be green because it had nothing to look at.
2. **Hand-typed strings stay a criterion in their own right (`A3`).** `A1` computes its expectation
   from the same rival set the code uses, so a wrong build whose defect is not in the rival set is
   invisible to it — measured: `Q28'` passes the suite, injectivity and `A1` on both corpora.
3. **The injectivity property is given an owner (`A4`).** It is the sole guard on three wrong builds
   and no `ABC-013` criterion requires it; it is asserted in this ticket's own rows so the guard does
   not depend on `src/san.test.ts`'s copy surviving.
4. **The SAN-shape property is NOT promoted, on a measurement** — it is blind to all six wrong
   builds. Refusing a cheap-looking criterion because it kills nothing is the same job as adding one
   that does.

## Size `M` (3), and `S` rejected deliberately

23 positions, 63 strings, six property/quantifier tests, one test file, zero production lines.
`ABC-023` and `ABC-024` are `S` at 16–17 rows; this is roughly four times that table. `ABC-013` was
`M` at 18 positions and 52 strings **plus** a 148-line module. Every position and string is supplied
verified, which is the argument for `S` and is why this is not `L` — but rounding a measured table
down to fit a precedent is how a ticket hides work, so **`M`, not rounded down**. The `L` shape is
named in the ticket (hand-typing all 132 grid rows) so nobody grows it into one.
