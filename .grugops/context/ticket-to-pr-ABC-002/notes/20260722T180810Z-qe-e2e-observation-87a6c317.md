QE result for ABC-002: **PASS, no defects found.** 22 tests in `src/moves.test.ts`, 49 in the suite, 0 skipped.

**All five acceptance criteria assert their exact stated number**, one test each, no restatement in the unit layer (the D-09 seam): 20 from the start position, 14 for the lone d4 rook, 2 for the a1 knight, the d4-rook blocking case (`d5` in, `d6`/`d7` out, `b4` captured, `a4` out), and the blocked-double-push case.

**Thirteen adversarial probes were run against the implementation before any test was written.** Ten confirmed behavior already covered. Two probes "failed" my own expectation and the generator was right, not the code: a rook boxed in by four friendly pawns returned 3 moves, and a bishop boxed in by four friendly pawns returned 4 — in both cases the boxed piece contributed zero and the extra moves belonged to the blocking pawns, which are the side to move as well. Worth recording because that is exactly the shape of a false bug report.

**Three probes found real gaps and became tests:**
- *Black from the starting position.* The acceptance criteria pin White only, and colour asymmetry lives entirely in the pawn direction and starting rank. A one-sided bug could have survived the whole suite. Returns 20.
- *Knight on h1.* The `a1` criterion covers the low-file corner. In 0x88 the off-board band sits on the **high**-file side, so an h-file wrap is precisely the failure the a-file case cannot catch. Returns 2 (`g3`, `f2`).
- *Queen ringed by eight enemies.* Asserts "the ray stops **on** an enemy" in all eight directions in one test; the rook criterion covers four.

**Cross-check performed but deliberately NOT added to the suite.** The generator returns **46** pseudo-legal moves for Kiwipete (`r3k2r/p1ppqpb1/bn2pnp1/3PN3/1p2P3/2N2Q1p/PPPBBPPP/R3K2R w KQkq - 0 1`), whose published legal count is **48**. The difference is exactly the two castling moves, which are ABC-004's scope — and in that position no white move is illegal by king-safety, so pseudo-legal and legal coincide for the rest. This is a strong correctness signal, recorded here rather than committed as a test for two reasons: ABC-002's test notes explicitly defer whole-position counts to perft (ABC-006), and the number must become 48 the moment ABC-004 lands, so a magic `46` in the suite would be a tripwire pointed at the next ticket. **ABC-004 and ABC-006 should expect 46 → 48 on this FEN**; if it does not, castling generation is wrong.

**Coverage: `src/` is 100% statements / 100% functions / 100% lines / 99.15% branch, against a `coverage_threshold` of 0.8. `moves.ts` and `position.ts` are 100% on every axis.** The one uncovered branch is `fen.ts:219`, pre-existing from ABC-001 and untouched here.

**Honest gaps, named rather than hidden:**

- **A pawn on the last rank returns 0 moves and does not crash.** Verified by probe, deliberately not committed as a test: the position is unreachable in a real game, and AGENTS.md rule 8 says not to test impossible scenarios. Noted so the next reader knows it was checked, not overlooked.
