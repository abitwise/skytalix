## 1. The geometry, re-measured rather than transcribed from the ADR

`renderBoard` returns 9 rows of 18 characters. `MESSAGE_ROWS` 2 + `PROMPT_ROWS` 1.
`frameHeight({9,3,8})` = **23**, `{9,2,5}` = **19**, `{9,4,9}` = **25**. `assembleFrame` with stub
arrays at 2/5 returns **19** rows; at 4/9, **25**. On a sink reporting `isTTY` and 24 rows,
`beginFrameSession` chooses **in-place at H = 19 / 23 / 24** and **append at H = 25**.

`assembleFrame` does **not** normalise height — 2/5 → 19 and 2/6 → **20** — so *"every frame's length
equals the session height"* is a real assertion. The frame's row count is **invariant under the
message region**: 0 items, 1 item, 200 items and one 100 000-character item all give 23, so deriving
the height from the *first* frame is safe whatever that frame carries.

## 6. Clause (a) has an instrument that needs no mocking at all

`beginFrameSession` reads `sink.isTTY` then `sink.rows` (`src/frame.ts:212`). Measured: a sink whose
`rows` accessor counts reads reports **1 read for one session and three writes**, and **2 after a
second session** — so "called exactly once" is observable with zero `vi.mock`. **The honest limit,
also measured: the `&&` short-circuits on a non-TTY sink, so the counter reads 0 there** and the
instrument only works on a TTY sink. Clause (b) needs the argument itself and therefore a spy:
`vi.mock("./frame.ts", importOriginal)` + `vi.fn(actual.beginFrameSession)`, the exact form merged
`src/gameend.nfr.test.ts:22-30` already uses — and it belongs in the file `A3b`/`A7b`'s spies already
require, because that file's own comment (`:12-15`) records that *"a `vi.mock` factory is hoisted to
file scope"*. **No new test FILE, which is `N8-LANE`'s binding risk.**
