# The named mutant dies as designed — and three others passed all eleven criteria while being real defects

A 29-mutant campaign was run against `src/glyph-mode.ts` (apply → run → restore, restoring from a
pristine copy every time). **28 die. One survives and is proven equivalent.** The module was
`cmp`-verified byte-identical to the pre-campaign copy after every pass and again at the end.

## First, the mutant the TICKET names by hand — established, not assumed

The `## Test notes` say: *"the implementation that reads `process.env` on every call passes all nine
table rows and must fail only these two [session criteria]. If a session test passes on that mutant,
the test is decoration."*

**It was built and run. It dies, and it dies to criterion 11 alone** — precisely what BA/PM rewrote
that criterion to do at the `Backlog` exit. **The correction did the job it was made for.** That is
worth recording as a positive result: the unfalsifiable-criterion fix was not ceremony, and the
`ABC-014` lesson transferred.

The ticket's other hand-named mutant — `if (process.platform === "win32") return "ascii"` — also dies,
to criterion 9 alone, which is why that test stubs `process.platform` rather than repeating row 5.

## THREE MUTANTS PASSED ALL ELEVEN ACCEPTANCE CRITERIA AND ALL 271 DELIVERED TESTS

Every one of them is a real production defect, not a stylistic variant.

### 1. The `LC_CTYPE` rung of the locale precedence was never pinned — and the ticket's own test notes forbid the shape that let it through

Two survivors: reordering to `LC_ALL > LANG > LC_CTYPE`, and promoting `LC_CTYPE` above `LC_ALL`.
Both went green on all 271 tests.

**The `## Test notes` say, in writing:** *"Test the `LC_ALL` > `LC_CTYPE` > `LANG` precedence with
conflicting values set at once, not one variable at a time. **One-at-a-time tests pass on an
implementation that reads the wrong one.**"*

Criterion 5 pins `LC_ALL` against `LANG` with both set. **Criterion 6 sets `LC_CTYPE` alone** — which
is exactly the one-at-a-time shape that sentence forbids — so the middle rung of a three-rung
precedence was never tested against either neighbour. The suite obeyed the note for one pair and
not the other.

This is a fourth instance of the family this ticket has now produced three times: **a criterion that
passes for a reason other than the one it was written for.** Criterion 6's real job is the
case-insensitive, hyphen-less spelling; it was carrying precedence it was never asked to carry.

### 2. A missing `isTTY` property was never constructed — and it is the only shape production presents

Node does **not** set `process.stdout.isTTY` to `false` on a pipe, a file, or CI. It leaves the
property **absent**, so the value is `undefined`. Every session test in the delivered suite rewrites
it to a real boolean via `defineProperty`, so the undefined shape — **the only one a non-TTY process
ever presents** — never reached `beginGlyphModeSession`.

Two survivors: `isTTY: process.stdout.isTTY ?? true`, and a `typeof … === "boolean" ? … : true`
guard. **Both read a missing property as A TERMINAL.** In production that sends Unicode into a pipe,
which breaks the determinism this ticket's own row-3 rationale promises `EPIC-006`'s pipe-driven
end-to-end test, and it defeats `RISK-005`'s fail-safe direction in the case that needs it most.
Both typecheck clean, so nothing else would have caught them.

### 3. The session was never pinned as EAGER

A lazy accessor that memoises on **first call** passed everything. Criterion 11 requests the mode
immediately after beginning the session, so it cannot distinguish eager from lazy.

Epic acceptance `2b` is *"decided exactly once, **before the first frame**"*. Lazy moves the decision
to whenever the first frame is drawn, and any ambient change in that window silently wins. The
Engineer chose eager deliberately and wrote *"true by construction"* in the module header — **the
choice is right, and nothing was holding it in place.**

## A fourth hole, in the `NFR-007` guard itself

`src/glyph-mode.nfr.test.ts` spied `node:fs` and `node:child_process` but **not `node:fs/promises`**,
which is a different module specifier. A mutant reading `/etc/locale.conf` through
`node:fs/promises` went green — **while the synchronous twin of the same read died.** The guard
existed against exactly this defect and had an async-shaped hole in it.

**The non-prefixed `fs` specifier was tested and DOES die** — vitest aliases it to `node:fs`. That
one was not a hole, and is recorded so nobody widens the guard for it.

## The single survivor, reported rather than hidden

**Dropping the `Boolean()` coercion on `process.stdout.isTTY` survives, and it is an EQUIVALENT
mutant** — proven, not argued. With the property absent, `Boolean(undefined)` is `false` and
`!false` is `true`; `!undefined` is also `true`. Row 3 fires identically. The new absent-property
test exercises that exact input and passes either way, which is the empirical proof rather than the
reasoning. **This is not a coverage gap and no test should be written for it.**

But the module's comment at that line says the coercion *"is doing real work and is not decoration"*,
and **that claim is false at runtime.** It is a type-honesty nicety. **Recorded as a comment defect,
not a code defect, and nothing was edited** — coding rule 9, and rewording another role's reasoning
to match a finding is how audit text stops being evidence.

## Flakiness, checked rather than assumed

The session tests rewrite real `process.env` and `process.stdout.isTTY`. **Five shuffled full-suite
runs (`--sequence.shuffle`) were clean, 271/271 each.** The `afterEach` restore from module-load
descriptors holds, and vitest's per-file isolation keeps the rewrites out of the other twelve files.
No flaky test was introduced and none was found.
