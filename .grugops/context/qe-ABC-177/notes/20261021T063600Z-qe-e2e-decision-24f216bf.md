# `ABC-177` timing-2: how owner amendment `…b87c35b6` was applied to the registered instruments (owner-delegated recommended options)

**The conflict.** `…b87c35b6` relaxes the foreign-free window. The registered instruments still enforce it:
- `timing/run.sh` admits a window only when `window.mjs` exits 0 (0 foreign polls).
- `readout174.py` and `readout-nfr008-174.py` discard any round with foreign samples, and a discarded round VOIDs the stage
  (n must be 8).

As registered, no reading could stand while any foreign load was on the host.

**Decisions.** All were fixed in `probe/timing2/preregistration-timing2.txt` at 05:58:00Z, before any arm build, window or
reading. They follow this project's practice of derivative instruments that change one thing.
1. **Branch rule.** A 180 s pre-sample is taken with the registered `window.mjs`.
   - 0 foreign polls: run `timing/run.sh` as is.
   - Otherwise: run `timing2/run-amended.sh`.

   The pre-sample read 5/181 foreign polls (another Claude session's vitest in `Projects/public/grugops`), so the amended
   branch ran.
2. **`run-amended.sh`** is `run.sh` with only these changes:
   - one 180 s `window.mjs` (unchanged), with a 5 s `pmset`/load1 poll beside it;
   - the window is admitted on AC at every poll, P1 before and after, and load1 ≤ 8 at every poll;
   - foreign polls are recorded, never gating;
   - outputs move to `<runid>/`;
   - both the registered readouts (the strict view) and the amended copies run;
   - `perrun.py` adds a per-run power/load1/foreign record and decides nothing.

   The lane block is byte-identical to `run.sh` (checked by `diff`).
3. **`readout174a.py` / `readout-nfr008-174a.py`.** One change from the registered files: the `foreign` and `sampler`
   discard reasons are logged, not discarded. Status, counts, **thermal**, n = 8, k, R, A1 and the bounds are unchanged.
4. **Re-run.** The full stage gets one re-run if H > 9.2 s with foreign load recorded, or if the stage is VOID. The lower
   reading stands. The bound is 60 min from the first window. Nothing is estimated.
5. **Cool-down before r2 (added after r1 VOIDed on thermal).** A watcher (`timing2/wait177.sh`) polled every 10 s. It
   launched r2 after 6 consecutive thermal-0 polls on AC, with a deadline of 06:47Z. It did not touch the thermal rule.
6. **`NODE_OPTIONS=--max-old-space-size=400`** was exported to the driver (dispatcher rule).
   - N8's command sets it already.
   - `npm test`'s script sets its own 128 for its vitest child, so the measured commands are unchanged.
7. **Launcher.** The driver was launched from a scratchpad launcher, so no ancestor command line matches the instruments'
   foreign regex. The window logs show 0 self-matches.

**Not decided here.** The thermal discard rule is a registered readout rule. Relaxing it is not QE's call, and it was not
relaxed.
