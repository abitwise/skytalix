# qe-ABC-298 QE's own code read of the build against `ADR-0077` d1–d3: every duty is kept as the text reads. Nothing found that breaks identity. Four readings and one gap, none blocking

QE, task `qe-ABC-298`. I read `git diff b9b8eee9 b40a2d7e -- src/` line by line: `src/moves.ts`, `src/legal.ts`, `src/transposition.ts`, `src/search.ts` and `src/engine.ts`, with the code around each change. **This is a reading of text.** The runs that check the same duties are in the stage-A readings note: SG1 (a) and (b), and the pin lanes.

## d2, the seam
- **`generateMovesFrom(position, from)`** (`src/moves.ts`):
  - It has the same guards as `generateMoves`' loop body: off-board, empty or enemy yields none.
  - It calls the same helpers: `addPawnMoves`, then `addStepMoves` or `addRayMoves`, then `addCastlingMoves` for a king.
  - `generateMoves` emits every castle after the whole square loop, so `filter(m.from === from)` keeps a king's steps before its castles. This function emits them in that order.
  - `addCastlingMoves` checks the king's identity on its home square, so a king off its home square gets no castle.
  - **`generateMoves` is not edited.**
- **`legalMoveFrom(position, from, to, promotion)`** (`src/legal.ts`):
  - It takes the one per-square move with that `to` and `promotion`, and always tests it with `staysSafe`. The king square is `move.to` for a king move, else `kingSquareOf`.
  - An unflagged move takes the board-only test. A flagged move (castle, en passant, promotion, double push) takes the full `makeMove`/`unmakeMove`. That is (1-A)'s form, and it skips none of its four classes.
  - It uses no pin scratch.
  - It does not check `move.from === from`, and needs not: every move `generateMovesFrom` returns has that `from`. The one exception is a board with two kings of one colour, where `addCastlingMoves` could offer the other king's castle. `parseFen` refuses such a board ("exactly one white king"), and play never makes one (QE-298-l, INFO).
- **`entryMoveLegal(slot, position)`** (`src/transposition.ts`):
  - It reads word 2 live (`table[(slot << 2) + 2] & MOVE_BITS`), the same read `entryMove` makes, and never `hitData`.
  - It unpacks `from | to << 7 | promotion << 14` as `packMove` packs it.
  - An empty word (0) asks for a1 to a1, which no generator emits, so it returns null. `entryMove` returns null there too.
- **Imports:** `transposition` → `legal` → `moves` / `apply` / `position`. No cycle.
- **`HASH_FIRST_DEPTH_LIMIT = 2`** is in `src/transposition.ts`, with § Context's reason in its comment.
- **No new `src/search.ts` or `src/engine.ts` export** (d2's dated line).

## d1, the gate and the sequence, in both recursions
- **The gate.**
  - **`src/search.ts`:** `slot !== -1 && depth <= HASH_FIRST_DEPTH_LIMIT && switches.ordering === "full"`. `slot` is −1 whenever `switches.table` is off, so "the table is on" is in `slot !== -1`.
  - **`src/engine.ts`:** `slot !== -1 && remaining <= HASH_FIRST_DEPTH_LIMIT`. The engine always probes and always orders in full: its 16 `chooseMove` entries hold no table-off or ordering door. **This is d1 as written (QE-298-j, INFO).**
  - Neither recursion's root (`searchRoot`, `runIteration`) is touched, and neither is `src/quiescence.ts`.
  - The gate sits below the leaf test, so the remaining depth there is 1 or 2.
- **The steps run in d1's order:**
  1. the repetition check, the leaf, `probeTable` / `tableCutoff`, and the null move, all unchanged;
  2. one live read of word 2;
  3. the hash move, made and searched by `searchMove` at index 0 with reduction 0. At index 0 `searchMove` takes the full-window branch, so the node's own window is used;
  4. the cutoff test `Math.max(alpha, hashScore) >= beta`, behind `prune` in `src/search.ts` as the loop's is;
  5. a cutoff writes `recordHistoryCutoff(position, HASH_CUTTER, 0, depth, false, previousCut)` behind the history switch, then `killers.record(ply, hashFirst)`, then `storeEntry(key, depth, boundOf(hashScore, alpha, beta), hashScore, ply, hashFirst)`, then returns.
  - Alpha has not moved at the cutoff test, so `alpha` there is the entry alpha. `boundOf(…, alpha, …)` is `boundOf(…, alphaIn, …)`.
  - **`src/engine.ts`'s make and unmake sit in `try` / `finally`.** An abort in the subtree unmakes, stores nothing and propagates (d3 item 1).
- **No cutoff:**
  - `legalMoves` runs, then `orderMoves` / `ordered`. Each gets `hashMove = hashFirst`, with no second read of word 2, and the countermove read before the subtree.
  - The index-0 bookkeeping is kept: `searchedQuiets` + 1 when the move is quiet and `moveLimit > 0`, `index` = 1, `best`, `bestMove`, and alpha raised (behind `prune` in `src/search.ts`).
  - The loop runs over `list.slice(1)` (d1's dated line).
  - A gated node whose word-2 move is not legal has `hashFirst` null and runs today's path. Its `hashMove` is that null, which by d2's oracle equals today's `entryMove(slot, moves)`.
