## G1 — the `thinking` flag is an INPUT that no criterion crosses with any content

`A7` is the only criterion that varies `thinking`, and it varies it on **one quiet position** after
`1.e4`. The consequence is that every cell's behaviour in the thinking state is unpinned.

| mutant | what it does | caught by |
|---|---|---|
| `m06` | drops `CHECK` while thinking | **nothing** (378/400 games diverge) |
| `m37` | emits `U+2718` in the check cell only while thinking | **nothing** — `A12` misses it |
| `m29` | drops the claim cell while thinking | 1 snapshot only |
| `m46` | drops the side-to-move cell while thinking | 3 snapshots only |

**`m37` is the sharp one**: `A12` is worded *"Given every case above"* and iterates `CASES`, and no
`CASES` entry is **both** `thinking: true` **and** in check. So the criterion that makes epic
acceptance `2a` hold *"by construction rather than by vigilance"* has a state it never visits.

**Cheapest close, and it is a test-note-shaped fix rather than a new criterion:** `CASES` gains a
`thinking: true` variant of the in-check case. That single entry closes `m06`, `m37` and the
`A10`/`A11`/`A12` sweep over it at once, because those three are already written over `CASES`.

## G2 — `A7`'s width clause cannot fail on the build it was written to catch

Measured at `A7`'s own fixture (numbers in the `observation` note): the panel's widest row is **row
2** at 21 characters and row 3 is 11, so `widestOf(idle) === widestOf(busy)` is **21 === 21** whether
the idle thinking cell is reserved, blank, or **dropped entirely**. `m23` — the dropped cell, which
is verbatim the build `D7` added this clause to kill — passes `A7` and every other criterion.

**This TOUCHES the live frame-width question and is deliberately narrower than it.** `ADR-0010`
landed on `main` while I was working and I read it before writing this. I am **not** asking for a
constant-width criterion — clause 5 refuses one and that refusal is not reopened here. I am pointing
at what clause 5 *kept*:

> *"Its `A7` (the reserved thinking cell) **stands** … `A7` is now a legibility clause (the row-3
> content does not jump horizontally)."*

**`A7`'s new and narrower rationale names row 3's own width. `A7`'s assertion measures the panel's
widest row.** Those are different quantities and the clause was already blind to the first before
`ADR-0010` narrowed it to exactly that. Under the old rationale the clause was wrong about which
quantity mattered; under the new one it is wrong about which quantity it measures. **One line closes
it in both the criterion and the test** — compare row 3's own length between the two states rather
than the widest row's — and it names no other module and no frame-level term, so `ADR-0009` clause 2
and `ADR-0010` clause 2 are both untouched. **Owner: BA/PM.** Architect/Design is owed nothing here;
this is inside `ABC-016`'s own row.

## G6 — `A9` claims a protection that no criterion CAN deliver

`A9`'s parenthetical: *"a panel that renders 'you' or **infers the claimant from anything but
`status.claimable.by`** reproduces the exact defect `ABC-020` exists to fix."* It kills the first
half — `m30` (`"You may claim:"`) died on `A8` and `A9`. It **cannot** kill the second: `m27`
diverged **0** times in 400 games, because `src/gameend.ts:170` reads

```ts
claimable: { by: position.blackToMove ? "black" : "white", draws }
```

The producer derives `by` from the same field the inferring panel would read, so against any status
the rules core actually produces the two builds are **definitionally identical**. This is `D17`'s
class exactly, and `D17`'s own remedy applies: state what the criterion protects and stop claiming
the rest.

**It is closeable rather than only strikeable, and I built the closing case to check.** Hand the
panel a `GameStatus` whose `by` disagrees with the position — the one input shape that separates
*reading* from *inferring*:

```
position 6k1/5ppp/8/b7/8/8/5PPP/4R1K1 w - - 100 60   (WHITE to move)
status   { claimable: { by: "black", draws: ["fifty-move"] } }

delivered panel renders:   "Black may claim: fifty-move rule"     <- reads `by`
an inferring panel renders: "White may claim: fifty-move rule"
```

The delivered panel is already correct. **Owner: BA/PM** — either add that case or narrow `A9`'s
parenthetical to the half it delivers. Doing neither leaves a reader believing they are covered.

## Flag 2 — the `1 - 0` ambiguity. **The premise is real; the discrimination gap is NOT. Take the one-liner anyway, for a different reason, and put it in the TEST.**

I measured the world rather than reasoning about it: **`withSan` = 2, `sanAlone` = 1.** The spy does
intercept `san.ts`'s internal call today, so we are in the `2 - 1` world and the assertion means what
it says.

**But the `1 - 0` world would not weaken it, and that is the part the flag does not state.** SAN's
own call enters `withSan` and `sanAlone` with the **same coefficient**, so it cancels exactly. Both
worlds, all three builds, measured for the intercepting column and derived for the other:

| build | intercepting (today) | non-intercepting |
|---|---|---|
| delivered | 2 − 1 = **1** PASS | 1 − 0 = **1** PASS |
| `m40` two calls always | 3 − 1 = **2** FAIL | 2 − 0 = **2** FAIL |
| `m41` second call only once a move exists | 3 − 1 = **2** FAIL | 2 − 0 = **2** FAIL |

**Identical verdicts.** The difference half measures the panel's own count correctly whether or not
the spy intercepts. So the failure the flag imagines — *"this assertion would stay green while
measuring something else entirely"* — does not occur: it would stay green **while measuring the same
thing by a different route.**

**Take `expect(sanAlone).toBeGreaterThan(0)` anyway**, and I agree it is the right line and not
`toBe(1)` — `> 0` names no number `src/san.ts` owns, so it is not the `ADR-0009` clause 1 fault that
got *"1 empty, 2 thereafter"* rejected. But the honest reason is **provenance, not protection**: in
the non-intercepting world `A13`-as-promoted would have been perfectly satisfiable and **`D19a` would
not have existed**. The whole routing of two hops turns on a number nothing in the repo records. That
line is the record.

**It belongs in the TEST, not the criterion.** It constrains the **instrument**, and a criterion is
about the panel. A criterion that pins the spy's plumbing is a criterion that goes red when vitest
changes its mock hoisting — which is the same class of foreign-ownership fault `A11`'s struck
`frameHeight(...) is 23` clause was struck for.

**One more thing at that exact site, and it is worth more than the flag is:** the far higher-value
line to add there is a **second ply depth** — gap `G4`. `sanAlone > 0` documents an instrument that
is working. A 4-ply case catches a regression that is not.
