# The epic size check: `L` no longer holds. It reads `XL` on what is CUT, and the largest part is still unsized

**Arithmetic, not feel.**

| half | tickets | points |
|---|---|---|
| runnable (`ABC-041`…`ABC-046`, cut 2026-08-13) | 6 | 13 (`S`+`M`+`M`+`S`+`XS`+`S`) |
| this hop (`ABC-100`…`ABC-102`) | 3 | 7 (`S`+`M`+`S`) |
| **counted total** | **9** | **20** |

The size was corrected `M` → `L` on 2026-08-13 against 13 points, with the prediction *"It will
likely reach `XL` once distribution is decided"*. **It reached the `L` ceiling before distribution
was decided:** 20 points is ~1.5× the figure `L` was assigned to. **Recommended: `XL`.**

`confidence: medium` and the reason is named rather than hidden: this project has **no published
points-per-t-shirt table for EPICS**. The `L` calibration is inferred from the 2026-08-13 correction
(*"the indicative `M` (3 points) is wrong by ~4x"* at 13 points), so `XL` here is an extrapolation
from one data point. **The direction is solid; the letter is a judgement.**

## Four things the 20 points do NOT include

1. **The packaging work itself.** Unsized because it is **unscopeable** until `ABC-100` lands — npm
   publish, a binary build and a documented clone are different jobs.
2. **Save/resume and PGN export** — the epic's own negotiable slice. **Correctly still uncut**;
   nothing has play-tested anything, and the epic says to cut them first if it runs long.
3. **The `EngineSeam` contract change** that lets a difficulty level reach an engine —
   Architect/Design's own ticket (`ABC-101` fences it).
4. **The turn-loop arm** for a state-changing command, if Architect/Design rules shape (b) —
   `ABC-046` already excluded it from this epic's arithmetic and `ABC-102` keeps that exclusion.

## The recommendation this produces — for the Orchestrator and the owner, NOT taken here

**`EPIC-006` should probably be two epics.** The evidence, not a preference:

- **The two halves share no dependency in either direction.** Packaging blocks nothing in the
  session half, and the session half blocks nothing in packaging. `ABC-100` is the only ticket in
  this epic that is INVEST-**independent**, and it is independent *of its own epic*.
- **The blockers are different in kind.** The session half waits on tickets and one architecture
  ruling — things this factory can clear. Packaging waits on **a human being asked a question**, for
  an unbounded time.
- **They fail differently.** An epic that cannot close because one criterion needs the owner's word
  will sit `In Progress` indefinitely and make every burn-down and every "is `EPIC-006` done" read
  wrong.

**Not done here** — the subtask forbids editing the epic, and splitting an epic is a decomposition
decision above one ticket-cutting hop. **Recorded so it is a choice rather than a drift.**

## The no-`XL` rule: NOT triggered

It binds **tickets**, and the largest ticket cut at this hop is `M` (`ABC-101`). **No
`SPLIT_REQUIRED`.** An `XL` *epic* is a signal to split the epic, not a gate failure.
