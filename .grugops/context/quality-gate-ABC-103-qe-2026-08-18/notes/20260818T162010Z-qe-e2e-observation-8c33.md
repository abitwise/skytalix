# WHAT THE DELETION LOST, measured on both sides — and it is exactly one thing

The question put to this hop was *"a deletion always shrinks detection somewhere; where?"*. It is
answerable precisely, because the deleted assertion was the **only** assertion in this repository
sensitive to the **CARDINALITY** of the flat production-module set. Everything else that reads that
set reads MEMBERSHIP: `toContain` in `src/cli.test.ts`, a `startsWith("cli")` equality at
`src/cli.test.ts:757`, a filtered-importer equality at `src/render-seam.test.ts:100`, and the
licence equality at `src/history-pane.nfr.test.ts:335`.

**Cardinality changes in two directions, and only one of them is a loss worth the name.**

**Direction 1 — an ADDITION now passes silently.** That is the ticket's entire purpose and is not
a defect. The honest framing is that the count could not tell an intended module from a stray one:
a scratch file, a backup, an accidentally committed `src/Untitled.ts` used to red the suite, and
now does not. The price was paid knowingly and the alternative — keeping a detector that cried
wolf four times in one day (`ABC-042`, `ABC-031`, `ABC-076`, `ABC-077`) to catch a stray file that
has never once occurred — is worse, and is the subject of the live `ABC-105`.

**Direction 2 — a DISAPPEARANCE now passes silently, and this is the real loss.** Measured, both
sides, whole suite:

- `src/perft-bench.ts` removed from the tree, delivered suite: **`npm test` 999 passed / 35 files, GREEN.**
- the same tree, with `src/cli.test.ts` restored from `7ea9e1b`: **RED**, `src/cli.test.ts:738`,
  `expected … to have a length of 23 but got 22`.

**The loss is exactly bounded, and the bound is what keeps this honest.** A production module that
is imported anywhere reds the suite by breaking its importers, so the count added nothing for it.
The count was load-bearing only for a module that **nothing imports** — which, by `ADR-0011`
clause 4, is precisely an **entry point** (*"a production module that exports nothing"*). Today
this repository has two entry points and only one of them is exposed: `src/cli.ts` is held by
`toContain("cli.ts")` and by 19 rows that spawn it, and `src/perft-bench.ts` is held by nothing
at all. **So the measured loss is one file wide.**

**It does not stay one file wide.** `ADR-0011` clause 4 states in terms that entry points are a
growing class and names `EPIC-006` as the trigger. Every entry point added there inherits this
hole on the day it lands, and `npm run perft` / `npm run chess` are the commands that break when
one silently vanishes — a break `npm test` will not report.

**No repair is proposed here, and that refusal is the recommendation.** Restoring detection means
re-asserting an inventory, which reinstates precisely the cry-wolf detector `ABC-103` removed. If
this is ever worth closing, the instrument is *"the modules that no other module imports are
exactly `{cli.ts, perft-bench.ts, …}`"* — a property, not a total — and it is a ticket of its own
with an `ADR-0011` clause 4 dependency, not a line to be smuggled into this gate.
