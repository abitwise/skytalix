# QE-189-a (LOW, proposed): the pin fixes bin's string, not its target. A build that stops emitting dist/uci.js passes every gate

- **Plant:** in a scratch export of head `91883f94`, `tsconfig.build.json` `"outDir": "dist"` → `"outDir": "build"`. Nothing else changes.
- **Result:**
  - `npm run build` gives rc 0, emits `build/uci.js`, and does not emit `dist/uci.js`;
  - `npm test` gives rc 0, 60/60 and 1995/1995;
  - lint and typecheck give rc 0;
  - A10 and the AR-168-BINPIN pin are green.
  So `bin` names a file the build no longer makes, and nothing goes red. The same class covers `files: ["src/cli.ts"]` (reasoned, not planted).
- **Read:** `grep -rn 'tsconfig.build\|dist/uci' src/*.test.ts` finds only the `build` script byte pin (`:1812`) and the new pin (`:1823`). Nothing pins `tsconfig.build.json`'s `outDir` or `files`.
- **Not against a criterion.** ABC-189's scope is the one assertion, and the page fences "proving the installed case" to a packaging ticket. This is a sibling of AR-168-BINPIN, not a hole in it: the (iv-b) mutant is caught.
- **Rating LOW:** the trigger is the same as AR-168-BINPIN's (packaging `dist/`, a backend depending on `skytalix`, or a `bin`/build edit). Nothing on the board does that today, and a dangling bin fails loudly at install or launch.
- **Route:** BA/PM records it. Either it rides on AR-168-BINPIN's trigger list, so the packaging ticket owes a "build emits what `bin` names" check, or an XS test-only cut pins `tsconfig.build.json` `outDir`/`files` beside the bin pin.
- **Also checked:** `dist/uci.js` at head after `npm run build` starts with `#!/usr/bin/env node` (3941 B).

QE-189-b (INFO): the pin is stricter than npm. A bare-string `bin`, `./dist/uci.js` and `dist\uci.js` go red, though npm 11.20.0 normalizes all three to `{ skytalix: "dist/uci.js" }`.
That is the safe direction: any `bin` edit is AR-168-BINPIN's trigger anyway, and the cost is a one-line re-pin. No action.
