# What this GATE does NOT establish — soft, non-load-bearing, explicitly unverified

`confidence: UNKNOWN - verify` on the whole note. Nothing here may be cited as settled. A PASS on the
`In Review` exit means the twelve criteria are met and the suite can now fail when they are not; it
does not mean the frame is right.

1. **"The frame is correct on a real terminal" is STILL NOT claimed, and this gate did not change
   that.** No test here attaches a TTY either. The screen model's four assumptions — `\n` implies a
   carriage return (ONLCR), the right-margin wrap is deferred, moving below the last row scrolls by
   one, `ED(0)` does not move the cursor — are stated in the file and were **not** verified against a
   terminal. **A specific one is worth naming for whoever can check it:** `EPIC-003`'s input surface
   (re-prompt, tab-completion) plausibly puts the terminal into raw mode, and whether raw mode
   preserves `ONLCR` on this platform's `termios` is **`UNKNOWN - verify`**. If it does not, this
   module — which emits no carriage return — draws a staircase, and no test in this suite would
   notice. `EPIC-006` is the first place it is observable.

2. **The screen model itself is unverified test code and was not proven correct.** It was shown to be
   **load-bearing** (a byte-only rewrite of two criteria survives a mutant the model kills) and to be
   non-permissive (it throws on an unmodelled escape), which is not the same as correct. One known
   limit: the model applies `ED(0)` from the cursor column even when a deferred wrap is pending, where
   a real terminal erases from the last written column. It cannot bite here — the frame's last row is
   the empty prompt row, so the cursor is at column 0 when the erase arrives — but it is written down
   rather than discovered later.

3. **The mutation campaign is a SAMPLE, not a proof.** 56 mutants is 56 hypotheses about how this
   module could be wrong, chosen by one reader of it. Four survived and are disposed of; six holes
   were found that the Engineer's own 18-mutant campaign did not. **That asymmetry is the argument
   against treating this note's own campaign as exhaustive.** "No further defect remains" is NOT
   claimed.

4. **The two equivalence proofs are arguments, not exhaustive checks.** `?? -1` versus `?? 0` and
   `sink.isTTY === true` versus `Boolean(sink.isTTY)` are equivalent **over the declared types and
   over every input a caller can construct today**. Both become distinguishable if `FrameSink` ever
   widens, or if a caller hands in a height of zero.

5. **The per-frame `W` is a demonstrated behaviour and an UNQUANTIFIED risk.** It was shown to leave a
   stale tail on the screen model. Whether it ever fires depends entirely on `ABC-016` and `ABC-017`,
   which do not exist — so the probability is not "low", it is **unknown**, and it will stay unknown
   until those panels state their widths.

6. **`NFR-002` is NOT verified by this gate.** One coarse single-sample sanity check agreed with the
   Engineer's in-memory figure to within 6%. It has no rotation, no repeated rounds, no independent
   second sample and no syscall in it. It is evidence that the claim is not off by orders of
   magnitude, and it is **nothing else**. `plans/nfr-catalog.md`'s row is untouched and undischarged.

7. **Coverage at 100% on all four axes is not evidence of correctness and is not offered as any.**
   Every one of the six holes this gate found was in code that was already 100% covered — line
   coverage said the branch ran, and said nothing about whether anything would have noticed a wrong
   answer.

8. **UAT and E2E are absent, not passed.** No CLI entry point until `EPIC-006`, zero runtime importers
