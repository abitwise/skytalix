# FLAG: this panel's WIDTH is not constant, and `src/frame.ts:179` makes it the whole frame's `W`

> **Hand-authored**, and a `claim` rather than an `observation` on purpose: the *measurements* below
> are measurements, but the assertion that this is a **defect somebody owns** is a judgement about
> merged code across three tickets, and it is not gate-adjudicable. `confidence: UNKNOWN - verify` on
> the disposition; the numbers themselves were run.

## Measured

The status panel's widest row, on delivered `src/status-panel.ts`:

| state | widest row |
|---|---|
| quiet starting position | **17** |
| both draws claimable | **67** |

A **50-column swing**, from the `CHECK` cell (+7 with its gap) and the claim cell (up to +55).
Neither reserves its width. `A7` reserves the *thinking* cell's width and is the **only** width
clause on the ticket. The engineer recorded this consequence honestly in its decision note §2 rather
than hiding it, and no criterion covers it.

## Why it is not cosmetic, read at source

- `assembleFrame` recomputes `width` **per frame** as the widest panel row and pads every row to it —
  `src/frame.ts:179`, `:182`.
- The in-place writer emits `CURSOR_HOME` + rows + `ERASE_TO_END_OF_SCREEN` in one write —
  `src/frame.ts:216`. **`\x1b[0J` erases from the END of the new frame downward. It never erases to
  the right of a row already written.**
- So when a claim expires — a pawn move resets the fifty-move clock, and the cell vanishes — the
  frame narrows and **roughly 50 columns of the previous frame survive on every row of the redrawn
  region.**

`assembleFrame`'s own comment states the assumption this breaks:

> *"`W` cannot be taken over the message rows too: a long rejection would then widen the frame, which
> is the one way content can break `4a`'s constant geometry. **The panels set `W`**; the message
> region is bounded BY it."*

The message region was excluded **because it was known to be variable**. This panel is variable too,
and by more.

## The board already recognises this class — for the sibling ticket

`ABC-017`'s board row reads: *"constant WIDTH is now a criterion because `src/frame.ts:179` takes W
as the widest panel row and the natural build is 0/14–15/16–17 chars at 0/80/300 plies."* That is a
**3**-column swing, on a `P2` `S` ticket, and it got a criterion. This panel's is **50** and has
none. The reasoning that produced `ABC-017`'s criterion applies here identically and more forcefully.

## Deliberately NOT taken on this ticket, and why

There are two defensible fixes and choosing between them is a **design and product** decision, not a
wording one:

- **(i) this panel reserves width for its variable cells.** Costs a permanently blank ~53-column
  claim area on every frame of the game. That is a visible product decision and **BA/PM will not
  take it alone** — it is also exactly the "unrequested flexibility / reserved space nobody asked
  for" shape that coding rules 5 and 7 warn about, and the engineer already declined it for these
  two cells with a stated reason.
- **(ii) `ABC-018` clears each row as it writes** (`\x1b[K` per line). Cheaper and better-looking,
  but it touches **merged** code and reads against epic `4b`'s *"erases … in one operation"* clause,
  which was itself written deliberately against a counted redraw.

**Owner: Architect/Design to rule; the Orchestrator to route.** Writing a constant-width criterion
into `ABC-016` would be me picking **(i)** silently, which is the same failure mode this hop is
correcting elsewhere.

## Not blocking, and the deadline is nameable

Nothing composes a frame **in a loop** until `ABC-019`, so no stale column can reach a terminal
before then. And no current criterion is violated **today**: epic `4a` is about row count only, and
`4b` is worded over *rows* rather than characters — a narrowed frame leaves no whole row of frame N,
only its right-hand columns. **So this is carried, not blocking.**

**The decision is owed before `ABC-019` merges** — that is the first moment a second frame is ever
written, and the first moment the bug can be seen.

## What `ABC-019`'s ticket may be owed, flagged and NOT carried to that agent

If the ruling goes to **(ii)**, the per-row erase lands in `ABC-018`'s writer, which `ABC-019` drives
and whose emitted stream `ABC-019`'s criteria assert over. `ABC-019` is being built **right now in a
different worktree**. I have **not** communicated with it and opened no channel; its ticket was read
on disk and nothing was written to it. This bullet exists so the Orchestrator can decide whether that
ticket is owed anything — that routing is the Orchestrator's, not mine and not a message for me to
carry.
