# How this gate closed the gaps, and the one cost it ADDED

Four choices that constrain later work. Each is recorded because a later reader would otherwise have
to re-derive it from the test file.

## 1. A FEN-TEXT ORACLE, not more snapshots

The Engineer handed over that **22 of the 24 snapshots were never hand-verified**. The two obvious
responses were both refused: hand-checking 22 more frames square by square does not scale and is not
re-runnable, and adding more snapshots would have deepened the same hole.

Instead the suite now derives the **whole expected frame from the FEN TEXT** and compares. The
oracle is deliberately a different implementation, not a paraphrase of `render.ts`:

- it expands the placement field **textually** and never calls `parseFen`, `squareAt` or anything
  that knows the 0x88 layout;
- the dark squares are built by **walking out from `a1` and flipping on every step along both axes**
  — the criterion's own words — rather than by the module's `(file + rank) % 2`;
- the file-label row is built by **placing each letter in the column its file's glyph occupies**,
  which is the property that row exists to have, rather than by repeating the module's `join`.

**It is not a tautology, and that was checked rather than asserted: it kills 8 of the 10 mutants on
its own.** The 22 unverified snapshots are now a redundant regression net over a proof, which is what
a snapshot should be.

## 2. STRENGTHEN, never rewrite, the Engineer's tests

Not one delivered test was edited or deleted, including the unfalsifiable assertion in criterion 2's
test. The falsifiable form sits in the QE block with a comment naming why the delivered one is
empty. Reasons: AGENTS.md rules 9 and 10, a diff a reviewer can read, and — the real one — **the
record should show which assertion was carrying which criterion.** Deleting the empty line would
have erased the evidence that it was ever empty.

## 3. The input domain was WIDENED to the module's real contract

Every delivered test enters through `parseFen`, which **requires exactly one king per side**. The
module's parameter is a `Position`, which is wider. So the suite had never rendered:

- a board with **no pieces at all** — the only input that shows all 64 shading characters with
  nothing standing on them (and the reason the shading rule is now proven over all 64 squares rather
  than at three named corners plus adjacency);
- a board with **all 64 squares occupied** — no cell takes the empty-square path;
- a board whose **off-board 0x88 half is full of junk** — the 128-entry array's odd half is padding
  (`ADR-0001`), and a renderer that scanned `0..127` or got the index arithmetic wrong would drag it
  into the frame.

All three are now tested and all three pass. This is the shape of gap the `ABC-012` review also
found: *every acceptance test anchored at one canonical starting point.*

## 4. Epic amendment `[A4]` is now a PROPERTY, and it is deliberately aimed at the next gate

`[A4]` says the shading is by CHARACTER and never by ANSI background. That was true and untested.
The suite now asserts **no ANSI escape and no control character in any frame**, over all 24 matrix
cells. It is also the **executable form of this ticket's "no security trigger" rationale** — "no
user-supplied string reaches this module; it renders bytes from `position.board`" — which
Security/NFR gates next, and which was prose in a ticket until now. It was proven to bite by
injecting `[40m` into the dark-square constant.

*(It was first written as a regular expression and `npm run lint` went RED on biome's
`noControlCharactersInRegex` — correctly. It compares code points numerically instead.)*

## THE COST THIS GATE ADDED, stated rather than hidden

The Engineer's hand-over item 2 warned that pinning "`a1` and `h8` are dark" by NAMING `:` means the
tests now encode a character CHOICE, and that **three assertions and the two hand-written frames**
move if a reviewer wants different shading characters.

**This gate raised that number.** The FEN oracle carries `":"` and `"."`, and so does the
all-empty-board frame. Changing the shading characters now moves **seven places**: three assertions,
two hand-written frames, the all-empty-board frame, and one oracle constant.

That is the right trade — an assertion that names no character is symmetric under inverting the
whole colouring, which is precisely how two of the Engineer's mutants survived — but it is a real
increase in the cost of one specific future change, it was incurred by this role, and a reviewer
who wants different characters should hear it from the record rather than from a failing suite.
`ABC-018` is where a human first sees these characters on a screen; that is the cheapest moment to
change them, and it is still cheap.
