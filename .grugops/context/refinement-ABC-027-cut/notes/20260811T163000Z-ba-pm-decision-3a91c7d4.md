## 1. `ABC-027` — size `S` (2), priority `P1`

`plans/tickets/ABC-027-frame-writer-clears-each-row.md`. Six criteria `A1`–`A6`.

**Size `S` (2), at the BOTTOM of the band. Explicitly not `XS`**, which this board argues each time
it declines it (`ABC-009`, `ABC-015`, `ABC-022`). The production side alone would be `XS` — one
expression and one constant, and I know that because I **built it**. What holds it at `S` is that
the test side is not one guarded condition: **five assertion sites across four tests**, one of which
is a characterization test that must be **replaced rather than deleted**, plus a criterion whose
**form is a judgement with three measured wrong answers**.

**Priority `P1`. Not `P0`:** `ABC-019`'s development is not blocked, and nothing composes a frame in
a loop yet, so no player can see the defect today. **Not `P2`:** it is a correctness defect in
**merged production code** that prints a wrong material count and keeps an expired draw claim on
screen; the owner's standing legality/correctness-first directive ranks a misreported game state
above renderer feel; and it is a hard predecessor of a `P0` ticket's acceptance that is
`In Development` right now. Unlike `ABC-017`, which its own ticket puts in the drop-first tier,
**this ticket cannot be dropped at all** without `ABC-019` merging minus the only criterion
`ADR-0010` cl. 7 requires.

## 3. The merge-order preference is DISPUTED. Recommendation: `ABC-027` BEFORE `ABC-017`.

The Orchestrator stated the two edges at different strengths and invited an argument on the weaker
one. **The FORCED edge is not disputed and is independently confirmed**: `ABC-027` before `ABC-019`,
because `ADR-0010` cl. 7's criterion fails on the merged writer at 80 and 120 columns and passes on
the clause-1 writer — re-measured here from the other side.

**On the PREFERENCE — `ABC-027` after `ABC-017` — the recommendation is the reverse, and it is a
RECOMMENDATION, not a forced edge.** Calling a preference forced is an error this round has already
recorded twice; this is not a third.

1. **`ABC-027` has exactly one ordering constraint and it is the forced one.** Measured: neither
   `src/status-panel.ts` nor a history-pane module exists on `main`, `ABC-027` imports no symbol from
   either, and the whole change runs **681/681 on 22 files, skip 0** with both absent. **`ABC-017` is
   not independent** — its own `A13` reads `ABC-016`'s exported `STATUS_ROWS` from delivered code and
   is *"not evaluable until `ABC-016` has merged"* (its words). The current order puts the dependent
   ticket ahead of the independent one on the path to the forced edge.
2. **The stated reason is spent.** *"`ABC-017` is sized and ready while `ABC-027` is uncut"* was true
   when written. `ABC-027` is now cut, sized, prioritised and DoR-complete; the gap is one gate move.
3. **The shared-file reason is weak in BOTH directions, measured.** `ABC-017`'s `A13` touches
   `src/frame.test.ts:38-45` and the assertions at `:288` / `:633`; `ABC-027` touches the screen
   model (`:203-207`, `:219-223`), `:374`, `:376`, `:419` and `:735-771`. **No line is claimed by
   both.** So it is not an argument for the current order either.
4. **The risk asymmetry is the real argument.** `ABC-027` changes a merged production expression that
   `ABC-019`'s Engineer is building against **right now**. `ABC-017` changes **zero production
   lines**. Landing the production change earlier puts the writer's final byte shape in front of a
   live branch sooner; landing the test-only change earlier puts nothing in front of it.
5. **The honest cost, stated rather than hidden — the dispute is CONDITIONAL.** `ABC-016` is
   `In Review`; when it merges, `ABC-017` becomes fully evaluable. **If a development slot opens
   before `ABC-027` is gated, pulling `ABC-017` first beats pulling nothing.** Gate `ABC-027` at this
   hop and it should go first; decline to gate it now and the original order stands and costs little.
   A rebase settles it either way, exactly as the Orchestrator said.
