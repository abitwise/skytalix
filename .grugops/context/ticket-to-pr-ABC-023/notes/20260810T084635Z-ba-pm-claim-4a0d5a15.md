# The soft parts of this hop, separated from the hard ones — the row count is an ESTIMATE, the ruling is a JUDGEMENT, and neither is stampable in this install

Recorded as a `claim` with `confidence: UNKNOWN - verify` because Workflow 16 step 4 leaves no other
honest option: there is **no `scripts/` directory in this repository and none in the kit root**, so
`context-io.ts` does not exist, Workflow 05 step 5's `emitVerdict` cannot run, and no live green
`§14-gate#<id>` verdict exists for a `finding` to reference. `context.human_admission` is `off`, so
there is no `human:<name>` stamp either. The engineer's and QE's notes on this point were checked at
the source rather than inherited, and they are correct. **These notes were therefore written by hand,
which is itself a departure from Workflow 16's "only via `context-io.ts`" and is recorded rather than
hidden — the alternative was to record nothing.**

**The measurements in the sibling `observation` note are NOT soft.** Every count there was run by me
at this hop. What is soft is below.

## 1. The row count in `ABC-024` is an ESTIMATE, not a measurement

**16 rows and 18 tests** is derived from the shape of the gap — 10 corridor squares, 4 forced scalar
rows, 2 controls, 2 quantifiers — and from `ABC-023`'s measured calibration (17 rows / 19 tests = `S`,
delivered as +375 lines). **I wrote no rows**, because `A4`'s additions-only rule and this subtask's
boundaries forbid it, so nobody has yet proved that 16 rows actually kill the seven mutants. The
discriminating requirements are stated per criterion precisely so the build hop can falsify the
estimate rather than inherit it. If the real number is materially larger, the size is wrong and the
ticket should be re-sized at the `Backlog → Ready` exit, not quietly overrun.

## 2. The `~+350 lines` security threshold is a projection

`+525` fires the security half; the `~+350` prediction it is set against is `ABC-023`'s **measured**
+375 for 17 rows scaled to 16. That scaling is arithmetic on one data point. It is deliberately
generous so the trigger fires on a genuine surprise rather than on ordinary variance, and it is a
number a future hop can argue with — which is the whole reason it is written down instead of "none".

## 3. The ruling itself is a JUDGEMENT, not a measurement

The six grounds under it are measured; that a guard protected only by an opt-in lane is *inadequately*
protected is a call about where this project wants its net. I own it. The strongest counter-argument
is recorded in the ticket rather than omitted: perft is the strongest oracle here, it caught all seven,
and duplicating it wholesale would be waste — which is why the ruling is bounded to "the deep lane is
the ONLY protection" and explicitly refuses to promote the lane into the gate.

## 4. What was NOT measured at this hop, listed so no one reads it as covered

- **`npm run perft`, any throughput, coverage or `NFR-001` figure.** Not run. The `198,175` count that
  appears elsewhere on this board is cited by others and was re-derived by neither this hop nor
  `ABC-023`'s.
- **The fifteen behaviour-equivalent controls.** Not re-run. `ABC-024`'s `A5` cites `ABC-023`'s QE hop
  for that starting state (625/625, deep 32/32, killed count zero) and says so in the criterion.
- **`npm run lint` / `npm run typecheck` on the repository.** Not run — this hop changed no `src/`
  file. `tsc --noEmit` was run 14 times inside the harness copy and exited 0 on every mutant.
- **Whether seven is the complete set of deep-lane-only survivors.** It is what my catalogue reached,
  aimed by the two QE named.
