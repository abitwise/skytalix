# A9 verified by name-set diff against the merge base, not by trusting the report — it holds exactly

`A9` is *"the only modified tests are the ones named in Test notes"*. It is the first criterion in
this project that permits editing an existing test, so it is the one an author is most able to
overrun without noticing. I verified it two ways and it holds.

## The baseline, and why it is `b1b96cd~1` and not `main`

`git merge-base HEAD main` is `d53ce31`, but this branch carries the whole
`architecture-audit-2026-07-29` line, including **`c05a83b`** — my own audit tests, which added the
dead-by-material table and the fifty-move boundary block. The state `A9` is about is the tree the
Engineer started from: **`b1b96cd~1` (`65cb789`)**, whose `src/gameend.test.ts` is 202 lines and
whose line numbers match the ticket's *Test notes* table exactly (27, 69, 142, 191, 195, 199). Using
`main` as the baseline would have made the audit tests look like `ABC-020` edits.

## Name-set diff — collected from the runner, not by grepping `it(`

`npx vitest run src/gameend.test.ts --reporter=json | jq -r '... ancestorTitles[0] + " > " + .title'`,
sorted, on a read-only worktree at `b1b96cd~1` and on the branch:

```
  BEFORE: 28 names        REMOVED: 4        ADDED: 15        UNCHANGED: 24
```

The **four removed** are exactly four of the five the ticket names:

```
  ABC-007 acceptance > reports a draw by threefold repetition when a position occurs a third time   (line 27)
  ABC-007 acceptance > reports a draw by the fifty-move rule when the halfmove clock reaches 100    (line 69)
  fifty-move rule … > draws at exactly 100 plies                                                    (line 195)
  fifty-move rule … > still draws above 100 plies, as a position loaded from FEN can be             (line 199)
```

## A name-set diff is necessary and not sufficient — so I diffed the bodies too

A test can keep its name and change its assertions. `git diff b1b96cd~1 HEAD -- src/gameend.test.ts`
shows the only pre-existing test **bodies** touched are the same five (the fifth, `does not draw at
99 plies`, keeps its name and gains the `.claimable` absence assertion the ticket asks for). Every
other hunk is a pure addition: three module-level helpers, the `ABC-020 acceptance` block, the
`the claimable set` block, and one import line. **No sixth test moved.**

`src/gameend.test.ts:142` — `prefers checkmate over the fifty-move rule when both could apply` — is
**byte-identical** to the pre-`ABC-020` tree, as the ticket instructs. It is the test that *looks*
like it covers G-1 and does not, and it was correctly left alone.

## The 18 whole-object `toEqual` assertions: untouched, and genuinely still meaningful

I counted them myself in the baseline file and got **18**, matching the design hop:

```
  ABC-007 acceptance   5   (fool's mate, stalemate, absent-from-history, K vs K, normal position)
  insufficient material 4  (the `draws` table)
  ABC-007 QE probes     1  (White delivers mate)
  dead by material      8  (2 dead rows + 6 alive rows)
```

The three `notDraws` rows and the two `.result`/`.reason` probes are **not** among them — they use
weaker assertions and were never at risk.

All 18 are byte-identical in the diff. **"Still meaningful" I measured rather than assumed:**
mutating `gameStatus` so `claimable` is always present (empty array when nothing is claimable) fails
**12 tests, 8 of them among the 18**. So they are not inert survivors of a shape choice — they now
additionally assert *"and nothing is claimable here"*, at no cost and with no edit, which is
precisely the free bonus the design hop predicted. Had the shape been a required claims field, an
empty-array sentinel, or a new tag field, `A9` would have been violated; it was not.
