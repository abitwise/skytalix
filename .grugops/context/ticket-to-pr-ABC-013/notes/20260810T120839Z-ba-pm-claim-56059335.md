# The criteria set is NOT certified complete — and this is the note that says so instead of the board

**Claim, unverified:** the repaired acceptance table of `ABC-013` catches every wrong build of
`toSan` that matters.

**I do not believe it, and nothing here establishes it.** It is recorded as a claim so that the
promotion this hop took cannot later be read as a completeness certificate.

## Why the prior runs against it

- Nine deliberately wrong builds passed the previous table — a table a careful pre-check had
  reviewed at this same hop and returned only four defects against.
- **One hole was in my own repaired table** and survived until a mutant ran: the rank-before-file
  build passed both the ticket *and* the first version of my repair, because the ticket's knight
  pair stands on one rank. If I had scored only the builds the pre-check suggested, that criterion
  would have shipped looking correct.
- This board's record: `ABC-018` five defects against a pre-check naming three; `ABC-009` seven
  against four; `ABC-022` seven against two; `ABC-023` six against three; `ABC-013` seventeen
  against four. **The opening count has been low five times out of five.** There is no reason to
  believe the closing count is now exact.
- `ABC-023`'s QE hop ran 67 mutants over three tree states and found **fourteen** builds that passed
  every criterion, the whole 578-test suite and deep perft 32/32 — after BA/PM had repaired that
  ticket's criteria at this same exit.

## The specific structural weakness

The reference `toSan` that scored the fifteen builds was **written by the same role that wrote the
rows**. It agrees with all 52 hand-typed strings, which is genuine corroboration of internal
consistency — the table was stamped before the implementation existed (`md5 56d56506…`, 11:51:22Z)
so nothing was derived from it. But a shared author is a shared blind spot: any rule I have wrong in
my head is wrong in both artefacts, and neither would notice.

**What would settle it:** QE's independent mutation hop, with a harness QE writes, over a mutant set
QE chooses. That is what `A5` needed on `ABC-023` and it is what this table needs. Until then, the
honest status of "the table is complete" is `UNKNOWN - verify`.
