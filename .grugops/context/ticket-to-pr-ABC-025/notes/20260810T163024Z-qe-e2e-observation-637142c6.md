# `N5` reproduces on a THIRD instrument — and the bar is also unmeasurable as written: its noise floor is four times the bar

Two separate statements, and they are not the same statement. **(1)** The breach the Engineer and
the Orchestrator reported is real and reproduces here. **(2)** `N5` names a wall-clock ratio and
**no statistic**, and on this machine the run-to-run spread of the *unchanged* lane is larger than
the delta the bar is about — which is a defect in the bar's specification, on top of the breach.
Neither is a verdict: `N5`'s owner is BA/PM and the ruling is the Security/NFR gate's.

## The measurement, and the instrument named honestly

**Nine INTERLEAVED rounds** of A → B → C (not nine of A then nine of B: a slow patch of the machine
must not land on one condition only), each condition a full `npx vitest run`:

```
A  neither hardening file          652 tests   wall min 1630  median 1773  spread 330 ms
B  ABC-025's delivered file only   672 tests   wall min 1774  median 1892  spread 252 ms
C  as this hop leaves it           676 tests   wall min 1722  median 1861  spread 281 ms
```

```
                     by wall MIN   by wall MEDIAN   by the file's OWN test time (isolated, 3 runs)
delivered rows           +8.8%          +6.7%       236 / 236 / 242 ms  = ~18% of the lane's own
                                                    reported test time (~1.33 s)
this hop's rows          -2.9%          -1.7%       6 / 6 / 6 ms        = ~0.4% of the same
```

**The bar is ≤ 5%. The delivered rows breach it on every statistic that can be computed: +6.7%,
+8.8%, ~18%.** That is a third independent reproduction — the Engineer measured +171 ms / 12.5% and
19.3%, the Orchestrator +182 ms / 10.3%, and this hop +8.8% / ~18%. The three disagree on the
magnitude and agree on the verdict, which is the honest shape of a noisy measurement.

## The part that is new: the bar cannot be measured with the instrument it names

`N5` reads *"the tests this ticket adds cost ≤ 5% of the default `npm test` wall clock."* On this
machine:

```
5% of the 652-test lane                       ~85 ms
widest within-condition wall spread (9 runs)  330 ms   -- the SAME tree, measured nine times
```

**The noise is four times the bar.** My own rows demonstrate it: they measure `-2.9%` and `-1.7%` in
the A/B — a negative cost, which is not a claim that adding tests makes a suite faster, it is the
instrument saying it cannot resolve 6 ms. The Engineer's +171 ms and the Orchestrator's +182 ms are
inside a ±330 ms band; they agree with each other, and they were each taken from three to six runs
of a lane whose spread they did not report.

**What would fix the bar rather than the ticket:** state the statistic and the sample. *"the median
of N ≥ 7 interleaved runs, or the file's own reported test time"* is measurable; a bare "wall clock"
is not. The file's own test time is the stable reading here — 236–242 ms for the delivered file
across three runs (Engineer 260–268, Orchestrator 264: agreement within ~10%) against 6 ms for this
hop's — and it is the reading I would put the bar against.

## What this hop's rows cost, so the ruling has both halves

**This hop's rows do not change the runtime picture.** The `N5` breach is the delivered `A1`'s, in
the shape the Engineer diagnosed, and this hop neither improved nor worsened it measurably.

## The one thing I found wrong in the evidence offered for the cheap fix

The Engineer's note records: *"across all 13 mutants the assisted-only and unassisted-only mismatch
counts are identical, so the clause changes no verdict in this set"* — offered as the measured
argument that `A1`'s unassisted half (the expensive half, ~174 ms) could be dropped.

**That measurement cannot come out any other way.** All 13 mutants live inside the disambiguation
and body logic, which reads the same rival set whichever call form supplied it: **no mutant in that
set can distinguish the call forms by construction.** The identical counts are a property of the
mutant set, not evidence about the clause.

Measured on four mutants built to be call-form asymmetric:

```
CF1  the mate test reuses the caller's PRE-move list (assisted never mates)  killed by A5, ABC-013 A19, N1
CF2  the mover excluded by reference identity (unassisted qualifies all)     killed by A1, A3 x10, A5, +13
CF3  no list generated when none is supplied (unassisted never qualifies)    killed by A1, A3 x8, A5, +6
CF4  the supplied list emptied before use (assisted never qualifies)         killed by A1, A4, A5, INJ, +1
```

Two consequences the ruling will want:

1. **`A5` is a mutant-killer, not merely corroboration.** The ticket and the Engineer both record
   *"no mutant in this hop's set turns `A5` red"* — true of those 13, false of the class. `A5` is red
   for **all four** call-form mutants, and for `CF1` it is one of only three rows in the repository
   that catch it.
2. **On these 49 mutants, `A1`'s unassisted half is not the SOLE killer of anything.** The
   unassisted call form is covered by `A3` (63 rows, unassisted), by `A5` (23 positions, both forms)
   and by `ABC-013`'s `A18`/`A19` (18 positions, both forms). Narrowing `A1` to the assisted form
   would leave the call-form class covered — over **41 positions instead of 207**. That is the real
   trade, and it is BA/PM's and Security/NFR's to make, not mine and not the Engineer's. I did not
   narrow anything.
