# THE SWEEP, RE-RUN INDEPENDENTLY — and the two count-shaped tripwires the sweep's own wording missed

## 1. The engineer's sweep is CONFIRMED, by this hop's own reading and its own `git diff`

`grep -rn "productionModules" src/` returns nine sites in three files. Neither
`src/render-seam.test.ts` nor `src/history-pane.nfr.test.ts` asserts a total on its
production-module listing:

- `src/render-seam.test.ts:88` defines the helper; its one consumer is `runtimeImportersOf` at
  `:100`, a **filter**. No `toHaveLength` and no `.length` reaches the listing.
- `src/history-pane.nfr.test.ts:163` defines `productionModulesIn`; its two consumers are `:322`
  (the licence **equality** at `:335`) and `:546` (a `FRAME_PRODUCERS` **filter** used as probe
  roots). Both are set relations.

Byte-unchanged is not asserted on the engineer's word either: `git diff --stat main..HEAD -- src/`
returns **`src/cli.test.ts | 13 +++++++------`, one file changed**, so neither swept file was
touched. `A3` MET.

## 2. `ADR-0011` clause 1's trigger check did NOT depend on the count — checked, not assumed

Nobody had looked, so this hop looked. `ADR-0011` never cites `src/cli.test.ts` at all
(`grep -n "cli.test.ts"` on the ADR: no match), and its only count-shaped language is descriptive
history — the *"identical 16-file set"* measurements at `:131`, `:171` and `:638`. Its clause 1
residual is **`R3`**, whose trigger is *"the **first `.ts` file under a subdirectory of `src/`**"* —
a MEMBERSHIP condition, detected by the `nested` equality, which this ticket left byte-unchanged
and which `M4`/`M5`/`M7` prove still fires. The ADR's one mention of `toHaveLength` (`:787`) argues
in the **opposite** direction: it records a drafted row proving a `toEqual` → `toHaveLength`
weakening would be caught. **Nothing in `ADR-0011` leaned on the deleted integer.** `A3`'s
out-of-scope fence was correctly drawn.

## 3. But TWO count-shaped tripwires on the module inventory SURVIVE, and one is 19 lines below the repaired row

The ticket's problem statement is *"any new file under `src/` that is not a test reds the suite,
with a failure that names neither the new module nor the reason, and the only repair is for a human
to bump the literal by hand"*. That is now **only conditionally** true.

- **`src/cli.test.ts:757`, the `A9` row.** `expect(productionModules().filter((m) => m.startsWith("cli"))).toEqual(["cli-options.ts", "cli.ts"])`
  is a hand-maintained inventory of a SUBSET, in the same file, 19 lines below the repaired row.
  **Measured (`M1`): adding `src/cli-placeholder.ts` reds the suite**, and the repair is exactly
  the reflex `ABC-103` was cut to abolish — a human edits a literal list he did not write in order
  to land unrelated work. The trigger is not hypothetical: `EPIC-006` is the CLI epic, and
  `ABC-101` (`--difficulty`) is the kind of ticket that adds a `cli-*` module.
  Its own comment (*"a third would put this row out of date silently"*) shows the row is deliberate,
  so this is **routed to BA/PM as a scope question, not called a defect**: `ABC-103`'s scope fenced
  itself to `:733`, and this row was never in it.
- **The `nested` equality that `ABC-103`'s rationale relies on is not about the entry point at all.**
  It filters `entry.includes("/") && entry.endsWith(".ts")` — every nested `.ts` in the tree,
  **including test files**, while `productionModules()` above it deliberately excludes `.test.ts`.
  **Measured (`M5`): adding `src/sub/foo.test.ts` — correct work, no wrong build — reds `A3` alone,
  with `expected [ 'sub/foo.test.ts' ] to deeply equal []`**, a message naming neither the entry
  point nor the reason. That is the same cry-wolf species the ticket removed, in the same `it`
  block, one assertion further down. It is **pre-existing** and was equally true before `ABC-103`;
  what is new is that the ticket's rationale now rests on this assertion and never examined its
  domain. **Not repaired here — narrowing it would weaken a live guard, which this hop may not do.**

Both are recorded for BA/PM. Neither blocks `ABC-103`.
