# qe-ABC-300 gaps: QE-300-a (A6, carried to ABC-282 A6), QE-300-b LOW, QE-300-c and QE-300-d INFO. None blocks merge

The ticket's `## Scope`, `## Out of scope` and `## Acceptance criteria` are the contract (`plans/tickets/ABC-300-…md`); they are cited, not restated.

- **QE-300-a. A6 `UNKNOWN - verify`, a named gap, carried to `ABC-282` A6.** Non-blocking by the ticket's own design (A6 "checked at `ABC-282` A6, not offline"; brief: no games).
  - **What is still owed:** at `ABC-282` A6's real run, QE reads `machine.txt` for `control: skytalix and base tc=40/8 timemargin=0 TimeMode=uci-clock-mode`, and `cmd.txt` for the A1 tokens as played. That run uses the real `cutechess-cli` and the real engines.
  - **Supporting evidence only, not A6:** one real `d --tc 40/8 --rounds 1 --concurrency 1` with fake tools (runs note). Its `machine.txt` has that line, its `cmd.txt` has the tokens in both blocks, `SHA256SUMS` verifies, the executed argv equals the dry print, and both builds advertise `TimeMode … var uci-clock-mode`. So the record path works today. Only the real tools' output is unread.
- **QE-300-b, LOW. Two scope items have no pair-check row.** Scope 3 (the `machine.txt` `control:` line) and scope 4's "before any build or process start" are uncovered. Mutant M7 (the line dropped) and M8 (the `--tc` checks moved after `git rev-parse`) each pass pair-check 45/45. QE's fake-tool real run kills M7 (0 `control:` lines), and QE's `PATH` probe kills M8 (12 of 14 refusals then start `git`).
  - Both behaviours are correct at `9835859d`, as QE's runs show. The offline net would not catch a regression in either.
  - Not a ticket miss: A1–A7 do not ask for either row. A6 reads the `control:` line at `ABC-282`, and A2 asks only for exit codes, messages and no argv.
  - Suggested follow-up, the Orchestrator's call, not this ticket's: a row in the next `tools/rating/` ticket that wraps `git` on `PATH` for one refusal.
- **QE-300-c, INFO. Duplicate flags: the last value wins.** `d … --tc 40/15 --tc 40/8` is accepted and prints the A1 vector, while `--tc 40/8 --tc 40/15` is refused.
  - This is the harness's existing rule for every flag. At the cut, `d … --budget-ms 500 --budget-ms 100` is accepted at `st=0.1`, and the order reversed is refused.
  - The ASVS L1 trigger still holds. Only the value that reaches the argv is validated, and it is the exact text `40/8`.
  - No action asked. Noted so that nobody reads it as a new hole.
- **QE-300-d, INFO. `40/8` is 40 moves in 8 seconds, and the SE decision note misreads it as minutes.**
  - The SE decision note `…a0bef530` says "a 40/8 2-game run is up to about 32 minutes on one core", which is 8 minutes a period. cutechess-cli reads `tc=moves/time` with time in seconds. `ADR-0071` D10 means seconds: it scales from the claim's `tc=40/900` and gives C 75–370 ms a move and about 22–24 s a game.
  - The harness emits exactly D10's token, so this is no defect. The upper bound for 2 games is 200 moves a side, which is 5 periods of 8 s, about 80 s a game plus starts.
  - Risk: the usage line (`--tc: D only, 40/8: …`) states no unit. A PREREG wall estimate for `ABC-282` A6 that repeats the minutes reading would be about 60× off. QE at `ABC-282` should take the wall from D10, not from the SE note.
- **Not a gap, checked:**
  - A refusal exits 1 with a Node stack trace after the `Error:` line, as every existing refusal does.
  - A `--tc` value containing a newline is refused, and the message spans two lines.
  - `--tc` swallows a following `--dry-run` as its value. That case is refused with no argv and no process.
  - `--tc=40/8` and `--TC` get the usage text.
  - The watchdog (600 s of silence) cannot trip on a 40/8 game: a move is capped at 60 s, and `-debug all` streams output.
