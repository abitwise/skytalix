# Two acceptance defects in `ABC-015`, ruled and corrected in place — before promotion, not after

The Definition of Ready's *"acceptance criteria clear, testable and measurable"* check **failed** on
this ticket as it stood at 18:17Z today. Both defects are the class this role's own hard limit
names: *a vague criterion is a defect the gate cannot catch and the engineer guesses at.* Both are
fixed in the ticket, with the reasoning in place so it can be checked rather than inherited.

## Defect 1 — an input tuple with no stated output

`--ascii` and `--unicode` arrive at this function as **two independent booleans** — argv belongs to
`EPIC-006` and this ticket takes the flags already parsed. So `(ascii: true, unicode: true)` is a
constructible input, and **rows 1 and 2 of the precedence table both match it.** The ticket declared
the two flags *"mutually exclusive"* and handed the rejection to `EPIC-006` as a cross-epic
obligation.

**That precondition is not held by anything merged.** `EPIC-006` is undecomposed; the obligation is
a note for a decomposition that has not happened. `ABC-018` — the first caller that puts a board in
front of a player, and the ticket this one must merge with or before — arrives first. So at the
moment this function acquires a caller, nothing rejects the conflicting pair.

An engineer had three defensible guesses and the ticket picked none: throw, apply the rows in order,
or let the later flag win. Three readings of one criterion is the definition of guessing.

**Ruled: the rows are evaluated in order, row 1 wins, the answer is `ascii`, and the function
neither throws nor prints.** Three reasons, in the order they carried weight:

1. **ASCII is the fail-safe direction.** It is readable on every terminal; that is the whole of
   `RISK-005`'s mitigation. A wrong ASCII board is legible; a wrong Unicode board is `????????`.
2. **It costs zero code.** An ordered table already yields `ascii` for `(true, true)`. This pins
   behaviour that falls out of the natural implementation, so a later "improvement" — a throw, or
   unicode-wins — is caught by a test instead of shipping. It does **not** add a branch, so coding
   rule 8 (no impossible-scenario handling) is satisfied rather than bent.
3. **The conflict-rejection policy stays in exactly one place.** Naming the conflict in a message is
   `EPIC-006`'s obligation. Duplicating it here is how two places come to disagree — and this ticket
   writes nothing and prints nothing by scope.

One acceptance criterion was added for the tuple. Nothing else in the table moved.

## Defect 2 — a criterion no implementation could fail

The ticket's ninth criterion read:

> **Given** a session that has selected a mode, **when** the selection function's inputs change
> mid-session (e.g. an env var is rewritten), **then** the mode already handed to the renderer is
> unchanged — the selection is made once, before the first frame, and cached.

**With the signals injected as arguments — which this ticket's own `## Test notes` require — the
only test that criterion admits is `const m = select(...); process.env.LANG = "C"; expect(m).toBe(…)`,
which asserts that a `const` does not mutate.** It tests JavaScript. It cannot fail. Its one failing
form — a module-level accessor that re-reads `process.env` on every call — is precisely what the
test notes forbid, because eight table rows cannot be exercised in one run against real globals.

**This is the same shape QE found in `ABC-014`** — *"not the white frame with its rows simply
reversed"*, which passed even under the defect it existed to catch. There it was found at the gate,
after the engineer had written against it. **Here it is found at the `Backlog` exit, which is where
it is cheap.**

**Replaced by two criteria that a named mutant kills:**

- the rule reads **no ambient global** — the same tuple returns the same value across a rewrite of
  `process.env` / `process.stdout.isTTY` between two calls;
- the session's value **survives** a rewrite of the ambient signals, **and** the rule called directly
  with the new signals returns the **other** value.

The second half is the load-bearing one: without it, "the value did not change" is satisfied by a
coincidence. With it, the test proves the cached answer is a cache. The named mutant — *reads
`process.env` on every call* — passes all nine table rows and must fail exactly these two; that is
written into the test notes so a future author cannot satisfy them with decoration.

## The ownership seam this exposed, closed rather than noted

Epic acceptance `2b` requires the mode to be *"decided exactly once, before the first frame"* and to
not change for the session. Who owns that?

- `ABC-015`'s `## Scope` and `## Out of scope` hand startup and argv to `EPIC-006`.
- `ABC-018`'s `## Dependencies` says *"`ABC-015` owns that rule and runs it once at startup."*

**Both point away from themselves, so no ticket owned the once-ness and no ticket could test it** —
which is exactly why the criterion that claimed it was unfalsifiable. A promise every document
attributes to a different document is not a promise.

**Ruled to `ABC-015`.** It is the ticket with the rule in it, it is already where the value is
produced, and `ABC-018` says so in its own words — so this ruling makes two documents agree rather
than making a third claim. **`ABC-018` and `EPIC-006` were NOT edited**: nothing in either had to
change, and this subtask touched no ticket but its own.

**Where the cache lives is NOT decided here.** A memoised accessor, a closure, or a value the caller
holds — that is structure and it belongs to the engineer (and to Architect/Design if they want it).
What this role fixed is the *observable outcome*: one value for the session, and a rule that reads no
ambient global so all nine rows stay testable in one run. This role does not design the system.

## What did NOT change, checked rather than asserted

**Size `S` (2)** — the corrections add one cached value and two tests; no argv, no I/O, no new module
of consequence. **Priority `P1`**, the five-row signal table, `## Out of scope` in full,
`RISK-005`'s severity and mitigation strategy, the `NFR-007` zero-I/O bar, the `## Dependencies`
section and its 2026-08-04 correction, and the **merge-with-or-before-`ABC-018`** constraint are all
untouched. The `Test notes` gained one line naming the mutant; the size rationale and the
Definition-of-Ready line gained the corrected count (eight tuples → nine, plus two session criteria).

## Scope discipline, stated because the temptation was real

Three things were considered and **declined as bloat**: a criterion for the positive `LANG` path
(already pinned by the `ISO-8859-1` bullet plus the default — see the observation note), a
`NO_COLOR`-style second capability decision (cut by epic amendment `[A4]`), and specifying the
module name or file layout (not this role's). **The feature you talk yourself out of is the one you
never maintain.**
