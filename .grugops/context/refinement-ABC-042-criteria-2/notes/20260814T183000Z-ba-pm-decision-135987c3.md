# `RF-7`…`RF-10` repaired: the clause as it stood, its replacement, and the build it now catches

Four changes, all in `plans/tickets/ABC-042-…md`, **zero code**. Security specified each replacement;
where the specification was itself loose I tightened it, and every tightening is called out below as
**TIGHTENED** with the hole it closes. Nothing was widened past a Security ruling.

---

## `RF-7` — MEDIUM — `A6`(i) had no instrument. → `A6`(i), now STRUCTURAL

**Was:** *"The accepted set is exactly `## Scope`'s closed table — asserted at the resolver: each
documented spelling resolves, and **no other token does**."* A universally quantified claim over an
infinite complement, whose only instrument on the page was `A6`(ii) — a random sample that catches a
targeted literal with **P ≈ 1.4e-9**.

**Now:** the accepted set is **DATA and the test asserts the DATA**. One **exported closed enumeration**
in the resolver; the test asserts it **equals `## Scope`'s table element for element, both ways, no
extras**, against its own transcription; **rejection is the DEFAULT branch** — membership is **exact
string equality**, and that enumeration is **the only argv literal in the delivered resolver, asserted
textually**.

**Catches, deterministically:** the resolver that quietly recognises `--debug` or `--engine-path` — **the
original HIGH's own build**, which was shipping green through every mechanically checkable instrument on
the page. It now has exactly two ways to exist and both are RED: put the flag in the enumeration (the
element-for-element equality fails) or write its literal elsewhere (the only-literal assertion fails).

**TIGHTENED, three ways, because Security's specification was loose:**
1. **"the accepted set is data" → "one EXPORTED closed enumeration", and `## Scope` 2 now says the
   resolver exports it.** A test cannot assert data it cannot reach, and the entry point exports nothing
   (`A2`) — so without this the clause was unimplementable in the delivered shape.
2. **"equals the table" → "element for element, both ways, no extras, against the test's own
   transcription."** One-directional equality passes on a subset; comparing the enumeration to itself
   passes on anything. The test must hold its own copy of `## Scope`'s table, or the criterion is a
   tautology.
3. **"deterministic against prefix-matching and case-folding" — it was NOT, so I added the instrument.**
   Data-equality alone does not catch `startsWith` matching or `toLowerCase()` membership: both keep the
   enumeration exact and write no extra literal. Measured, those two mutants (`M4`, and case-folding)
   escape `A6`(ii) as well — `0/10` seeds. `A6`(i) now derives, **from the table so it cannot go stale**,
   each spelling's upper-case form, `+"x"` extension and one-character truncation, and requires each to be
   rejected **in its legal argv position**. The position clause matters: bare `WHITE` is rejected by the
   case-folding mutant too, so only `--colour WHITE` distinguishes it. **Checked before shipping the
   clause: the 18 derived tokens collide with the accepted set 0 times**, so it cannot false-RED a legal
   build (`…observation-8fa9604a` §3).

## `RF-8` — MEDIUM — `A6`(ii)'s filter was ambiguous. → `A6`(ii)

**Was:** *"filtered to exclude every spelling in the accepted set"*, over *"1000 generated tokens … in the
shapes"*. Read as *drop any argv CONTAINING an accepted token*, the `--colour <word>` shape goes to **0 of
1000** and the `--colour <anything>` build ships green.

**Now:** **filtered by WHOLE ACCEPTED FORM only** — *"dropped only when the whole argv is `--colour
white|black|random`, `--ascii`, `--unicode` or empty — **never because it CONTAINS an accepted token**"* —
**and 250 tokens from each of the four shapes, with each shape's 250 asserted AFTER filtering and BEFORE
the rejection property.**

**Catches:** `--colour <anything>` (measured `5/5` seeds under the whole-form reading), plus the classes
`A6`(ii) already killed — any unknown `--flag` ignored, rejection without naming the token, short flags
eaten.

**TIGHTENED — this is why both readings now catch it, which the disambiguation alone would not do.**
Security asked for *"at least N tokens"* per shape. I made it a **fixed per-shape quota of 250** asserted
after filtering, for two reasons:
- **Both readings are now safe.** A reader who still applies the containment reading filters the
  `--colour <word>` shape to 0 and the quota assertion goes **RED** — the ambiguity can no longer produce
  a silent green, only a loud failure. That is the property asked for; a prose disambiguation on its own
  relies on the reader having read it.
- **A floor would have been a flake generator.** With shapes drawn at random, a `≥ 200` floor sits ~3.6
  standard deviations out — a genuine ~1e-4-per-run red on a correct build, in a shared lane, in a repo
  that refuses to put a wall clock in the suite (`A11`). A generated quota has **no** flake and starves
  no shape by construction.

## `RF-9` — MEDIUM, a guaranteed false RED on a legal build — `BAR 1b`. → call sites

**Was:** sentence 1 permits `execFileSync`; sentence 2 forbids *"**Zero** occurrences of `exec` and
`execSync`"*, *"asserted textually over the delivered diff"*. The delivered test file **must** contain
`process.execPath` — every spawn-provable criterion depends on it — and both it and `execFileSync`
contain the substring `exec`. The bar contradicted itself one sentence apart.

**Now:** **"Zero CALL SITES of `exec(` and `execSync(`"**, with the reason stated inline so a reader
cannot re-derive the substring reading: *"call sites, NEVER occurrences: the file MUST contain
`process.execPath`, and that and `execFileSync` both contain the substring `exec`."*

**Catches / stops catching:** it stops REDding the correct build and merged green code, and still reds
`cp.exec(`, `child_process.exec(`, `exec (`, `execSync(`, `cp.execSync(` — verified by execution
(`…observation-8fa9604a` §2). It permits nothing unsafe: this was a false RED, never a false GREEN.

**TIGHTENED:** Security's fix was the phrase *"call sites"*. A phrase is what produced the defect in the
first place, so the page now carries **the two regexes** — `/\bexec\s*\(/` and `/\bexecSync\s*\(/` — and
the measured baseline (**3** substring hits, **0** call sites on the cited precedent). The word boundary
sits between `.` and `e`, so member-expression call sites are still caught; `\s*` covers `exec (`.

## `RF-10` — LOW — bar 4's grammar missed `node:http2`. → one token

**Was:** `/^(node:)?(fs|net|http|https|tls|dns|dgram)(\/|$)/`
**Now:** `/^(node:)?(fs|net|http|http2|https|tls|dns|dgram)(\/|$)/`

**Catches:** a production module importing `node:http2` / `http2` / `node:http2/x`. **Completeness, not a
live hole** — there is no `http2` anywhere under `src/` today, and the production floor is zero
non-relative imports.

**TIGHTENED (by verification, not by wording):** I ran the amended grammar against `http2-wrapper`, the
prefix case Security's 27-specifier table did not include, because a new alternative is exactly how an
anchor gets broken. It does **not** match. **`node:inspector` stays out** — Security ruled it a debugger
surface with a named compensating control, and widening past that ruling would start the unclosable list
it declined.
