## QE-189-a (LOW, proposed): ACCEPT, no ticket
- **Fold is not available.** `AR-168-BINPIN` is closed, and no packaging or backend-dependency ticket exists to fold into.
- **Why not cut:**
  1. **No consumer exists.** Nothing on the board packages `dist/` or launches `skytalix`. Every path to a consumer goes through `AR-168-BINPIN`'s old trigger (packaging `dist/`, or a backend taking `skytalix` as a dependency, D8 revisit / `ADR-0018`). The ticket that path cuts must prove the installed launch anyway, because ABC-189 fenced that out to it. That one check (pack → install → `.bin/skytalix` answers `uciok`) catches all four measured plants. A static pin catches three, and is blind to P4, a base `tsconfig.json` emit change.
  2. **The failure is loud where it matters.** Measured: a dangling `bin` installs silently (rc 0, no `.bin` link, 0 warnings), and the first launch fails with rc 127. It is never a wrong engine that runs.
  3. **Every drift path is a build-config edit.** That means `tsconfig.build.json`, base `tsconfig.json` emit options, `bin` or `build`. Only a ticket diff makes such an edit, and the rule below puts a reader there. That is the QE-196-a shape, not QE-195-a's (where an unrelated refactor drifts with no reader).
  4. **The only complete automated check does not fit.** It needs a build in the default lane: one `tsc` run, about 0.6 s wall, against `NFR-008` headroom of about 0.6 s to 10 s. The static pin is cheap but partial. That is diminishing returns on a LOW that gates nothing.
- **Acceptance rule (BA/PM-owned, for tickets this role cuts):** any ticket whose diff touches `tsconfig.build.json`, the base `tsconfig.json`'s `compilerOptions`, `package.json` `bin`, or `scripts.build` carries one criterion. After `npm run build` at head, every path in `package.json` `bin` exists, and its first line is `#!/usr/bin/env node`. QE reads that at the hop, as `qe-ABC-189` already did by hand (`…c55e148e`).
- **Reopen triggers.** At any of these, cut the check as an XS ticket, or fold it into the triggering ticket:
  - **(R1)** a ticket is cut that packages `dist/` for anyone, or makes a backend depend on `skytalix`. That ticket carries the installed-launch criterion: `npm pack`, install into an empty scratch consumer, then `printf 'uci\nquit\n' | node_modules/.bin/skytalix` gives `uciok` with rc 0. Measured shape: P0 passes, P1 gives rc 127.
  - **(R2)** a dangling `bin` is ever observed on `main`, by any hop.
  - **(R3)** `bin` gains a second command, or `tsconfig.build.json` `files` gains a second entry. Hand reading then no longer scales, and the static derivation pin is cut.

## QE-189-b (INFO): agree, no action
- Stricter than npm is the safe direction. All three spellings are `bin` edits, which fall under the acceptance rule above, and the cost is a one-line re-pin.
- Matching npm's normalisation would mean importing npm internals into a test, or re-implementing them. That is bloat.
- **Reopen:** if the project ever adopts a `bin` spelling other than the object form on purpose.

## QE-189-c (INFO): agree, no action
- QE's `UNKNOWN - verify` is now measured on two paths:
  - `package-lock.json` is not in the `npm pack` tarball, so a consumer never reads the root entry;
  - `npm install --package-lock-only` rewrites a drifted root `bin` from `package.json`.
- So the drift has no install effect and heals at the next lock write. It is outside ABC-189's fence.
- **Reopen:** if any tool or test starts reading the lock root's `bin`.
