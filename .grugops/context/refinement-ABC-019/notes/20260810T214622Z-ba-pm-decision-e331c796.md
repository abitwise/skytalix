## The five rulings this hop had to make

1. **The render cadence is `1 + plies + non-advancing prompt outcomes`, not "one render per ply".**
   Forced, not preferred: the initial position must be rendered before the first act (or the player is
   asked to move blind), and a rejection line has no channel but the frame's own message region. `A2`
   is therefore **three** frames for one full move, not two. The old criterion was arithmetically
   unsatisfiable by any correct build.

2. **The exit test sits between `render` and `act`, and that position is normative.** The `## Scope`
   pseudocode's `while not terminal:` at the top can only read a status computed before the previous
   act — one ply stale. A new criterion (`A7b`) spies both seams at exactly zero calls after the
   terminal status is computed, because that is the only assertion that catches it.

3. **The binding NFR clause is a spied call count, not a clock.** The `≤ 100 µs @ 120 plies` number is
   **kept unchanged** and two ply counts are added (`≤ 45 @ 40`, `≤ 200 @ 300`), because the quantity is
   `O(plies)` by construction and one point cannot describe a line. But the number is not what pins the
   rule: a two-derives-per-ply build passes at 0.94x. `repetitionCounts` and `gameStatus` exactly once
   per ply, zero on a non-advancing outcome — the sixth bar on this project to move off a clock and
   onto a count, following `ABC-016`'s `A13` and `ABC-017`'s `A11`.

4. **The fifth prompt outcome's boundary is settled one-directionally.** Both tickets claimed it:
   `ABC-019` said *"this loop provides the fifth prompt outcome's transition"*, `ABC-021` said *"one new
   prompt outcome, one terminal transition"* — and neither had a criterion for it. **`ABC-019` owns
   that `game-over` is reachable from `awaiting-human` at all** (the machine admits a terminating prompt
   outcome; the terminal type has room for the two claimed values, `A14`). **`ABC-021` owns the `claim`
   outcome itself** — transition 16, its message, its fixtures. `ABC-021`'s side is **flagged, not
   edited**: it is outside this hop's lane.

5. **`ABC-016` is a CORRECTNESS dependency of `ABC-019`, not a rendering one.** `A5` and `A6` require a
   frame re-emit **without** re-evaluating, and a panel that derived its own status per frame made both
   **false**. `ABC-016`'s refinement deleted that call and its `A13` spies it at 0. `ABC-019` now states
   the other half — **the loop passes the render seam the `GameHistory`, the `GameStatus` it evaluated
   this ply, and the `thinking` flag; the render seam derives nothing** — which is the line `ABC-016`
   was owed and the routed item this hop was handed. It is also what keeps `NFR-002`'s `O(window)`
   statement standing, since that row voids itself if a renderer ever pulls the repetition derive into
   a frame.
