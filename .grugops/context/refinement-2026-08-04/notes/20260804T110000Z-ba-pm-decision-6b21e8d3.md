# ITEM 1 RULED: `ABC-022` cut, `S` / `P1`, straight to `Ready` — and it does NOT go ahead of `ABC-012`

The item routed to BA/PM by three roles across `ABC-011` and cut by none is now owned. It was
**reproduced by this role before being cut** — the reproduction and its three divergences from the
prior descriptions are the `observation` note beside this one, and the ticket is written against my
own measurements rather than against any summary of theirs.

## What was cut, and why it is one ticket rather than one or two

`ABC-022 — generateMoves offers en-passant captures its own preconditions forbid`, at
`plans/tickets/ABC-022-en-passant-generation-preconditions.md`.

It covers **both** missing preconditions of the en-passant branch in `addPawnMoves`, not only the
routed one:

- **(a)** the ep target is not checked to be empty → a capture is offered onto the mover's **own**
  piece, and `legalMoves` passes it through. *(The routed half.)*
- **(b)** the captured pawn's presence is not checked → `legalMoves` **permanently corrupts** the
  position. *(Never routed as an item of its own, and the worse of the two.)*

**One ticket, and the reason is INVEST rather than convenience.** They are the same `if`, the same
fix site, the same test table and the same regression walk. Two tickets would edit the same four
lines, which is the opposite of independent, and whichever landed second would re-open the first's
gate. This is the same argument `ABC-020` used for not splitting the FIDE 9.6 backstops out.

**Also stated as a scope bound rather than left implicit:** it does not touch `src/legal.ts` or
`src/zobrist.ts` except for one comment correction, does not re-open `ABC-011`, and does not overlap
`ABC-009` (different function) or `ABC-010` (different layer).

## Size `S` (2)

Two conditions in one branch of one function, one test table, one regression walk over an existing
position table, two comment corrections. No new module, no new export, no new dependency edge, no
design question — the fix site, the preconditions and the oracle are all named on the ticket.

Calibrated against `ABC-009` (*"one guarded condition plus two test shapes"*, `S`) and against
`ABC-011`'s second hop, which Architect/Design sized as *"smaller than the delta that took it
`S` → `M`"* for the identical shape. **Not `M`** — what took `ABC-011` to `M` was a new exported
predicate and a ratified reading, and this ticket has neither. **Not `XS`** — two independent
preconditions with disjoint failure modes, in the search hot path, with a mutation-hardened table.
**Not a split candidate**, per above.

## Priority `P1` — and this is the question the Orchestrator's note left open

**Applied on this board's own `P0` test**, written here by BA/PM on 2026-07-31 under the owner's
legality-first directive and never overturned: *"`P0` on this board now means the owner's directive
applies **and** the fault is reachable."*

- **The directive applies.** This is a move-legality defect in `generateMoves` — the query that
  defines which chess moves exist. Not by analogy: it emits a capture onto the mover's own piece and
  the legality filter passes it through.
- **The fault is NOT reachable.** Measured: **0 of 518,474 reachable nodes** carry an occupied ep
  target. It needs a semantically invalid FEN; `EPIC-003` is undecomposed and the only position any
  epic accepts today is `ABC-012`'s `newGame(initialFen)`, supplied from inside the product.

So `P1` — **exactly where `ABC-009` landed, on the same test, on the same day, for the same reason.**

**Why not `P0`, stated so it can be argued with.** The strongest case for `P0` is that this is a
legality defect in the most load-bearing module and the owner's directive puts legality first. The
answer is that the directive was already applied to this exact class on 2026-07-31 and produced `P1`
for `ABC-009`. Ranking `ABC-022` `P0` would place it **above** `ABC-009`, which is not defensible:
`ABC-009` is reached through `gameStatus`, which calls `legalMoves` on its first line every ply — a
strictly wider surface than this one has. Two tickets in one class cannot be ranked by which was
found most recently.

**The directive is honoured rather than overridden.** It re-ranks correctness against features, and
it does here: both rules-core defects sit above the `P1` renderer ticket. What it does not do is rank
a latent defect above the tickets the product's existence rests on — that reading was considered and
rejected in writing on 2026-07-31 (*"demoting them would model the directive as 'stop building the
game', which it does not say"*), and nothing found at this task disturbs it.

## THEREFORE: `ABC-022` DOES NOT GO AHEAD OF `ABC-012`

Said plainly because the routing note made this the open conditional — *"if it lands `P0` it goes
ahead of `ABC-012`"* — and the honest answer is **no**. `ABC-012` is `P0` and reachable; `ABC-022` is
`P1` and latent. Checked rather than assumed: `ABC-012`'s `## Dependencies` names `ABC-011` alone,
its positions come from inside the product, and nothing in its test notes is shaped around this
defect, so there is no sequencing constraint pulling `ABC-022` forward either.

## The two traps, verified rather than inherited

**Trap 1 — perft. The conclusion holds; the stated mechanism does not.** The note says perft cannot
clear this because the legality filter later rejects the over-offered move. **Measured, the filter
does not reject it.** Perft is silent because the trigger population is empty. This makes the
conclusion **stronger** — no perft depth and no added perft position can ever reach the defect — and
it is load-bearing for the ticket, which forbids adding a perft case and uses a constructed table
instead. Detail in the `observation`.

**Trap 2 — `ABC-011`'s guard (a). Confirmed, and stronger than QE put it.** QE corrected the
Engineer that guard (a) covers two classes and only one is this defect. Re-derived by deleting guard
(a): the predicate answers `true` on **both** classes, because `hasLegalEnPassant` synthesises its
probe and never consults `generateMoves`. Guard (a) is a precondition of the **predicate**, not
compensation for the **generator**; fixing `ABC-022` changes neither row. **"Deletable" is not
over-stated — it is false.** The ticket carries QE's correction and goes past it, and puts the
measured mutant table in a section of its own so a later reader inherits the correction rather than
the original framing.
