# The instrument, its two detectors, its arming controls, and the ONE thing it measurably cannot see

> **Hand-authored**, no stamp — see the sibling premises note for why. Everything here was built and
> run out of tree; artifacts to reproduce it are in
> `.grugops/context/quality-gate-ABC-028-instrument/artifacts/`.

## The instrument, in one paragraph

**The pane is handed a `Proxy` of the caller's `GameHistory` graph, and every write through it is
recorded at the instant it happens** — so a mutation restored before the render returns is still on
the record. That is what makes it an interval instrument rather than the before/after pair `D26`
already ruled out. **Two detectors, because each closes a hole the other measurably has:**

| | what it is | what it catches | its measured hole |
|---|---|---|---|
| **D1 write trap** | `set` / `defineProperty` / `deleteProperty` on every node reached through the view | every write to every ordinary slot, instantly, restore or no restore | a write that reaches the board through `board.buffer` never passes a trap |
| **D2 board digest** | the raw 128 board bytes re-compared at **every** trap of any kind, so each read the pane makes is also a sampling point | `.buffer` aliasing and the TypedArray methods | a mutation applied AND reverted between two samples |

**The write trap PERFORMS the write (`Reflect.set`) rather than blocking it.** Blocking turns a
detection into a crash and changes the wrong build's behaviour; detect, pass through, report.

## The mistake this instrument made first, measured and then fixed

**Before the fix, a wrong build that mutated the board with `board.set(...)` produced
`TypeError: this is not a typed array` and ZERO recorded violations** — every `%TypedArray%.prototype`
method throws when `this` is a Proxy. That is precisely the `ABC-017` fixtures-hop failure shape:
*"instrument broken"* announced where the truth is *"property violated"*. **Fix, measured:** a view's
methods are bound to the raw board, so the mutation happens for real and D2 reports it. Re-measured
after the fix: `board.set(other)` → 1 violation `[board-digest]`, `board.fill(0)` → 1 violation, and
reads (`board[0]`, `board.length`, iteration) → no throw, no violation.

*(The harness itself produced one false clean during this work — `fill(0)` read clean because an
earlier probe had already zeroed that fixture's board and the next baseline was the previous probe's
damage. Fixed by a fresh fixture per probe. Recorded because it is the same class of error.)*

## The kill matrix — every build, every one of `A1`'s ten lengths

Each build is the delivered source text plus **exactly one anchored edit**, generated by
`artifacts/make-mutants.ts` from the object database and md5-checked against
`54fd4346dcc1a0060c4e66ae0149265d` before generation. **All of them render byte-identical output to
the delivered pane at all ten lengths** — verified first, because a build that changes output is not
a survivor and proves nothing.

`W` = killed by the write trap, `D` = by the board digest, `WD` = both, `clean` = no violation **and
the instrument looked**.

- **The four builds `A4` names are killed at all ten lengths.** `WSPLICE` (`must STAY dead`) is killed
  by the new instrument as well as by `A9`'s freeze.
- **`WBOARDSET` and `WBOARDBUF` are mine, not the ticket's** — a board mutation by TypedArray method
  and one through an `ArrayBuffer` alias. Both survive the delivered suite; both die here. They are
  reported because they are the two shapes that would have made a `Proxy`-only instrument a false
  green.
- **`WBOARDBLIND` is the measured boundary and it is NOT killed.** It mutates the board through a
  `.buffer` alias and reverts it **with no intervening access to the graph**, so no sample falls
  inside the window. This is not a defect of this instrument in particular: **a synchronous call can
  only be observed at the points where it touches instrumented state**, so `.buffer` aliasing is
  detectable only by sampling and sampling is defeatable by a short enough window. It is named here
  so the criterion is not written as an absolute it cannot hold.

## The arming controls — the thing this ticket family got wrong once

**Per slot, not in aggregate**, so a hole in one slot cannot hide behind another. Each hostile writes
to one slot through the handed-out view; the instrument must report.

```
initialFen                    fired  [write-trap]
position.fullmoveNumber       fired  [write-trap]
position.blackToMove          fired  [write-trap]
position.board element        fired  [write-trap, board-digest]
position.board via .buffer    fired  [board-digest]
the moves SLOT                fired  [write-trap]
the moves CONTENTS            fired  [write-trap]
a Move's own field            fired  [write-trap]
null control (no mutation)    DID NOT FIRE          <- the positive control
```

**And the arming COUNTER, on the delivered pane, per length** — how many times the instrument looked.
Never zero, which is the assertion that separates "reported nothing" from "never got to look":

```
0:5   1:40   3:135   19:763   20:832   40:982   80:1485   120:1896   300:3484   2000:18677
```

## Two facts the criterion's author needs

1. **The instrument covers MORE than `A4`'s table.** `position.castling`, `position.epSquare`,
   `position.halfmoveClock` and the fields of every `Move` object are covered by the same trap, at no
   extra cost. That is what `## Test notes` 1 asked for — the property stated **once over the graph**
   instead of once per node, which is the pattern that produced four repairs.
2. **`Object.freeze(view.moves)` records 21 write-trap violations** (freeze is `defineProperty` per
   element plus `preventExtensions`). **`A9`'s instrument and this one must never be applied to the
   same object in the same test.** They are not today — every fixture is freshly built — but the next
   hop into this file should know.
