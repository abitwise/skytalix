# 24 mutants: the four enemy admissions DIE, all fifteen equivalents STILL SURVIVE — and one residual survives, measured rather than argued away

## Instrument, and the traps it is built against

Every mutant applied to a **copy** of `src/` held **outside** the repository with `node_modules`
symlinked. Each asserts its anchor occurs **exactly once** in the pristine source and that the bytes
**actually changed** — otherwise `HARNESS-ERROR`, never `SURVIVED`. `npx tsc --noEmit` per mutant, so
a build that does not compile is scored `BROKEN-BUILD` and never a legitimate survivor (three
`noUncheckedIndexedAccess` controls were correctly scored that way on an earlier hop, and a
non-compiling control once produced 147 failures nearly read as "the rows over-fit"). `src/moves.ts`
restored and **re-hashed to `0e247853ab2c05887c76105ff83d8621` after every mutant**, and the
repository's own `src/` was never mutated at any point (`git status --short -- src/` shows only the
one test file). **One process per tree, everywhere** — every `tsc`, every `vitest` and every harm
probe is its own OS process, because the module-cache trap gave an earlier hop a false *"the harms
don't reproduce"* by looping four tree states inside one process.

input, and each was chosen so that every OUTCOME assertion still passes:

Without the byte assertion the first two are invisible; without the inertness assertion the third
would stay green on a build whose identity guard was deleted. The test file was restored
byte-identical afterwards and the tree re-run green.

## The residual, measured on `A11`'s own rows so it is not mistaken for something this hop introduced

An admission conditional on the castling **side** for one type survives the net: enemy `KNIGHT`
admitted only QUEENSIDE, enemy `PAWN` admitted only KINGSIDE. The reason is structural — at `A11`'s
established doubling each type's two configurations vary **colour**, and the two `KNIGHT` rows are
both kingside while the two `PAWN` rows are both queenside. The colour-conditional versions **do**
die, each to exactly the one row that exists for it, so the doubling is load-bearing on the axis it
varies.

**This is inherited from that doubling standard, not created here — measured rather than asserted:**

```
A11 residual: KING's sq admits own ROOK only QUEENSIDE     tsc 0 · full suite 381/381 · SURVIVED
A11 residual: KING's sq admits own BISHOP only QUEENSIDE   tsc 0 · full suite 381/381 · SURVIVED
```

`A11`'s own `ROOK` and `BISHOP` rows on the king's home square are both kingside, so the identical
class survives there. **`A11` is not reopened by this and neither criterion is in shortfall** — both
require ≥2 configurations per type with all four rights across the table, and both have that. Closing
the class means widening **both** tables, which is a net-widening change beyond `A13`'s stated
eight-configuration region, and it is the same "a mutant conditional on X survives a finite net"
property `A13` already names. It belongs to the follow-up hardening ticket for `src/moves.ts`.

## What this observation does NOT establish

- **That 24 mutants is a campaign.** It is not; this role ran 62 at its first hop and called that
  not-a-proof. These 24 attack one dimension and the equivalence set that bounds it.
- **That the fifteen survivors are behaviour-equivalent in general.** They survive **this suite** over
  **these** positions, which is weaker than equivalence. Nothing was re-enumerated here.
- **That no further dimension exists.** `A13` exhausts the occupant byte; the joint pair space and the
  unvaried constants are named, reserved and NOT closed.
- **Any `NFR-001`, perft, coverage or throughput figure.** None measured by this role at any hop.
