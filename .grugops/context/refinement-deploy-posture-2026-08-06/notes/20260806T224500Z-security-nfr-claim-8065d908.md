# CLAIM (forward-looking, not a measurement): no epic on the current roadmap creates an availability obligation

This is the one part of the availability ruling that **cannot be verified by looking at the
repository**, so it is recorded as a soft claim rather than folded into the `decision` note's
evidence. The ruling itself does not depend on it — the ruling rests on what exists **today**, which
is measured in the sibling `observation` note. This claim only supports the **trigger's shape**.

## The claim

**On the roadmap as currently written, nothing in `EPIC-001`–`EPIC-006` ships a component that must be
reachable while its user is away from the keyboard**, so no scheduled milestone turns an availability
SLO into a real bar.

## What was actually read, so the confidence can be checked rather than inherited

For all six epics: `## Scope`, `## Out of scope`, `## Risks` and `## NFR triggers`.

- `EPIC-001` rules core — no surface. `## Out of scope` sends search to `EPIC-004` and rendering to
  `EPIC-002`/`EPIC-003`.
- `EPIC-002` terminal board and loop — output plus the loop skeleton; `[A4]` even defers ANSI colour.
- `EPIC-003` move input and controls — a typed prompt. `## Out of scope` declines arrow-key
  navigation, voice, mouse and config-file keybindings.
- `EPIC-004` engine — in-process search. `RISK-002` / `RISK-003` are about throughput and strength.
- `EPIC-005` opening book — a compiled data artifact. `RISK-004` is a licensing question.
- `EPIC-006` session and packaging — **the strongest evidence, and it is a product ruling rather than
  this role's reading:** `## Out of scope` names *"Network or multiplayer play — **permanent
  non-goal**"* and *"Accounts, cloud sync, ratings, or a stored game history database"*.

## Why this is `medium` and not `high`

1. **It is a statement about a backlog, and a backlog changes.** `EPIC-006`'s own text has been
   amended twice already this month. The *"permanent non-goal"* is BA/PM's and the owner's to reverse,
   and reversing it **is** the trigger recorded in `plans/nfr-catalog.md`.
2. **Section-level reading, not whole-file reading.** The four sections above were read in each epic;
   the full bodies were not. A network dependency hidden in a test note or an amendment block would
   have been missed.
3. **Nothing here was measured**, because there is nothing to measure — which is the whole point of
   the ruling this claim supports.

**A `claim` can never satisfy a `finding`'s admission and none was attempted.** Whoever revisits this
at `EPIC-006` should re-read the epics rather than inherit this note.
