# ABC-172 QE ruling on the lock: A2 literal is right; the license line is ABC-169's drift and lands separately, not here

Evidence (scratch copies only, `npm install --package-lock-only --ignore-scripts`, npm 11.20.0):
- Base lock + base package.json (name still `cli-chess`) regenerated -> ONE added line, `packages[""].license: "UNLICENSED"`. The drift exists at base, without the rename. It dates from `b3fecb1b` (ABC-169 added `license` to package.json and did not regenerate the lock).
- Base lock + branch package.json regenerated -> three lines (two names + license). That regenerated lock differs from the branch lock by exactly that one license line. No version, resolved URL, integrity or dependency moved.

Ruling:
1. **A2 literal governs.** Acceptance is the contract (the outer loop). Scope 2's "regenerate, not hand-edit" is a method, and test note 2 states its purpose: to keep A2 at two lines and stop resolved versions moving. Its premise, that regeneration yields exactly the two name lines, was broken by ABC-169 before this ticket started. The delivered lock is the regenerated lock minus one line that ABC-172 did not cause. The method's purpose is met (no version moved, `npm ci` rc 0 in a real install). The deviation is recorded (`20261021T135341Z-software-engineer-decision-e3f11766`), minimal and correct. It is not a FAIL.
2. **The license line lands separately, not here and not never.** It is not here because it would break A2 and A5 (A5 allows only the rename) and it belongs to ABC-169's lineage. It should not be dropped forever because the lock then disagrees with package.json and every future `npm install` re-adds it as unexplained noise in someone else's diff. Recommended home: the next ticket that legitimately regenerates the lock (ABC-168 adds `bin`/`build`/`uci` to package.json) with that line named in its criteria, or a one-line chore.
