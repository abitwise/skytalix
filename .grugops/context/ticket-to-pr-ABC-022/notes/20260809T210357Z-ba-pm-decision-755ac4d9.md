## The `A9` interaction — the load-bearing operational call, and `A9`'s text does not change

Sites 4-6 land in **`src/legal.test.ts`, an existing test file**. The engineer's chosen instrument —
`git diff --name-only --diff-filter=M main -- 'src/*.test.ts'` being empty — **will go non-empty.**

**That is a collision with the instrument, not with the criterion, and `A9` is therefore left
untouched.** `A9` requires *"no existing test is modified — verified at line level"*. A comment-only
edit modifies no test. The engineer chose a **file-level** check deliberately, and said so, to make
`A9` *"a fact rather than a judgement about which changed lines were tests"* — a good instinct that
happens to be stronger than the criterion. The replacement is the line-level filter the same engineer
**already applied to `src/legal.ts` at the same hop**: every `+`/`-` line of
`git diff main -- src/legal.test.ts`, stripped of its marker, must begin with optional whitespace and
`//`. Plus: no `it`, `describe`, `expect`, FEN string or table entry may change, and the suite's test
count must stay at **439**.

I verified this is achievable rather than asserting it: **`npx vitest run src/legal.test.ts` is
31/31 green on the branch tip with the file unmodified**, so every assertion in it already passes
against the fixed generator. Only the prose is false. **If the engineer cannot meet the line-level
form, the instruction is to stop and hand back rather than widen `A9`.**
